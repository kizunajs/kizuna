---
title: k.api
description: Assemble a contract and everything that serves it into the object your framework mounts.
---

`k.api({ contract, ... })` turns a contract into the object your framework mounts. Route handlers come from the routes themselves, so what is left is one guard per identity, one resolver per request context, the handlers for jobs and tools, and each plugin's server half.

```ts title="server/api.ts"
import { k } from '@/contract/k';
import { contract } from '@/contract';
import { requireUser } from './guards';

export const api = k.api({
    contract,
    guards: {
        user: requireUser,
    },
});

api.mount(app);
```

## Parameters

| Field            | Required                                    | Description                                                           |
| ---------------- | ------------------------------------------- | --------------------------------------------------------------------- |
| `contract`       | Yes                                         | The contract from [`k.contract`](/docs/reference/k-contract)          |
| `guards`         | When the contract declares identities       | One [guard](/docs/reference/server-guard) per identity, keyed by name |
| `requestContext` | When the contract declares request contexts | One resolver per declaration, keyed by name                           |
| `jobs`           | When the contract declares jobs             | One handler per job                                                   |
| `tools`          | When the contract declares tools            | One handler per tool                                                  |
| `plugins`        | When the contract installs plugins          | Each plugin's server half, keyed the same way                         |
| `adapter`        | When `new Kizuna()` declares none           | The framework to serve on                                             |

Each part is required exactly when the contract declares something for it, so a forgotten guard is a type error rather than a request that gets through.

## `mount`

`api.mount(...)` takes whatever the adapter's framework takes: an app for Express, Fastify and Hono, and nothing but options for Next, which returns the route handlers to re-export.

```ts title="server.ts"
const app = express();

api.mount(app);
```

## One contract, several frameworks

The adapter usually sits on [`new Kizuna()`](/docs/reference/kizuna), where it types the `req` and `res` every handler receives. A contract served on more than one framework declares none there and names the adapter per api instead:

```ts title="server/api.ts"
import { expressAdapter } from '@ts-kizuna/express';

export const api = k.api({
    contract,
    adapter: expressAdapter,
    guards: {
        user: requireUser,
    },
});
```

Handlers then receive no framework request object, which is what lets the same routes serve every adapter.

## Typing a guard in its own file

`Guard` types one identity's guard against the contract, so guards live beside each other rather than inside the `k.api` call:

```ts title="server/guards.ts"
import type { Guard } from '@ts-kizuna/core';
import { contract } from '@/contract';

export const requireUser: Guard<typeof contract, 'user'> = async ({ bearer, deny }) => {
    const session = bearer ? await db.sessions.findByToken(bearer.token) : null;
    if (!session) {
        return deny({
            status: 401,
            body: {
                detail: 'Unauthorized',
            },
        });
    }
    return {
        userId: session.userId,
    };
};
```

`params` carries the path parameters of every route whose `auth` names that identity. `RequestResolver` does the same for a request context resolver.
