<BetaNotice>

MCP support is new and still settling. The plugin options and the published tool surface may change while v2 is in beta, so pin your version if you depend on them.

</BetaNotice>

Serve an [MCP (Model Context Protocol)](https://modelcontextprotocol.io) endpoint as part of your API. Name it under `plugins` on [`defineConfig`](/docs/reference/define-config) and `api.mount` serves it, on every adapter.

<InstallTabs packageName="@kizunajs/mcp" />

```ts
import { mcpPlugin } from '@kizunajs/mcp';
```

## Parameters

```ts
mcpPlugin(props?: McpPluginProps): PluginDeclaration
```

| Parameter | Type             | Required | Description           |
| --------- | ---------------- | -------- | --------------------- |
| `props`   | `McpPluginProps` | No       | Configuration options |

## Props

| Option           | Default                                      | Description                                                                       |
| ---------------- | -------------------------------------------- | --------------------------------------------------------------------------------- |
| `slug`           | `'mcp'`                                      | What handlers reach this plugin under                                             |
| `path`           | `'/mcp'`                                     | Path the endpoint is served from                                                  |
| `name`           | `'MCP Server'`                               | Human-readable name shown to AI assistants                                        |
| `version`        | `'1.0.0'`                                    | Semantic version string                                                           |
| `instructions`   | built from your groups                       | Appended to the generated overview                                                |
| `oauth`          | off                                          | Serve the endpoint as an OAuth 2.1 resource server ([guide](/docs/mcp#oauth))     |
| `allowedOrigins` | localhost, and the `oauth` resource's origin | Browser origins allowed to call the endpoint ([guide](/docs/mcp#browser-origins)) |

## Which routes it publishes

The plugin takes no list of routes. Each route decides for itself, by declaring [`tool`](/docs/tools):

```ts title="src/routes/weather.ts"
getForecast: k
    .route({
        method: 'GET',
        path: '/forecast/:city',
        summary: 'Look up tomorrow forecast for one city',
        tool: true,
        responses: {
            200: ForecastSchema,
        },
    })
    .handler(/* ... */),
```

A route with no `tool` is an HTTP endpoint and nothing more. Two shapes never publish even with it: a route whose `contentType` is `multipart/form-data` or `application/x-www-form-urlencoded`, because tool input is JSON, and a route whose response [streams](/docs/streaming), because a tool result is one value. A [hidden](/docs/routes#hidden-routes) route can't say `tool`: the two together are a type error.

## Example

```ts title="kizuna.config.ts"
import { defineConfig } from 'kizunajs';
import { expressAdapter } from '@kizunajs/express';
import { mcpPlugin } from '@kizunajs/mcp';
import { routes } from './src/routes';

export default defineConfig({
    adapter: expressAdapter(),
    routes,
    plugins: [
        mcpPlugin({
            name: 'My API',
        }),
    ],
});
```

```ts title="src/index.ts"
import kizuna from '../kizuna.config';

kizuna.api.mount(app);
```

## Next.js

The endpoint is served by the catch-all route file that already serves your routes, so `path` resolves under its `basePath`:

```ts title="src/app/api/[...kizuna]/route.ts"
export const { GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS } = kizuna.api.mount({
    basePath: '/api',
});
```

With the default `path`, the endpoint is at `/api/mcp`.

## Secured routes

Each tool call runs the same [guard](/docs/reference/k-identity) pipeline as an HTTP request, reading credentials from the MCP transport request's headers. A `deny(...)` becomes a tool error result; with [`oauth`](/docs/mcp#oauth) configured, denials from that identity answer at the HTTP level instead. See the [MCP guide](/docs/mcp) for configuring clients to send credentials.

## Origin

Every request's `Origin` is checked before a guard or a tool runs. A request with none passes, as clients outside a browser send none. One that carries an origin passes when it is localhost on any port, the origin of the `oauth` `resource`, or listed under `allowedOrigins`, and answers `403` otherwise:

```ts title="kizuna.config.ts"
mcpPlugin({
    allowedOrigins: ['https://app.example.com'],
}),
```

Each entry is one exact origin, with no path, trailing slash or wildcard.

## Plugin route

The endpoint is a [plugin route](/docs/extend/create-plugin#routes), which is hidden, so your fetch client, the OpenAPI document, and the generated Swift and Kotlin clients never list it.
