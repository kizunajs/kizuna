---
title: k.contract
description: Assemble route groups into the Contract your server, clients, and generators all read.
---

`k.contract({ routes, jobs, accessControl, plugins })` bundles your route groups into the `Contract`, the one object you hand to the [client](/docs/reference/kizuna-client), [server](/docs/reference/server-api), and generators. It carries the routes, the access control resolved onto them, plus the tags, identities, and `issueCodes` you configured on `new Kizuna()`.

Every client imports it, so the contract and everything it imports travel with them. It holds route shapes, and server config stays in the API app. See [the contract guide](/docs/building/contract).

```ts title="contract/index.ts"
import { k } from './k';
import { routes } from './routes';
import { accessControl } from './access-control';

export const contract = k.contract({
    routes,
    accessControl,
});
```

`accessControl` is the map built with [`k.accessControl`](/docs/reference/k-access-control) beside the routes. `k.contract` also accepts it written inline.

The declared `issueCodes` widen `errors[].code` on `400` responses to `ValidationIssueCode | <your codes>`, so the client suggests them in autocomplete. Emit them at runtime with [`k.issue`](/docs/reference/k-issue). The factory is per API, so codes and tags stay scoped to it.

## Jobs

Jobs declared with [`k.jobs`](/docs/reference/k-jobs) go under `jobs`, beside `routes`:

```ts title="contract/index.ts"
export const contract = k.contract({
    routes,
    jobs,
    accessControl,
});
```

A job carries its own identity, so it takes no entry in the access control map, and it stays out of `contract.routes`, the OpenAPI document, and the generated Swift, Kotlin, and MCP surfaces. See [Jobs](/docs/jobs).

## Plugins

Plugins go under `plugins`, keyed by the name your handlers read them under:

```ts title="contract.ts"
export const contract = k.contract({
    routes,
    accessControl,
    plugins: {
        mcp: mcpPlugin({
            name: 'My API',
        }),
    },
});
```

Write it as a function to get the routes, which is what types props keyed by route name:

```ts title="contract.ts"
export const contract = k.contract({
    routes,
    accessControl,
    plugins: ({ routes }) => ({
        audit: auditPlugin(routes, {
            skip: {
                health: true,
            },
        }),
    }),
});
```

Their routes are served by `api.mount` and stay out of `contract.routes`, so the client and the generators do not see them. Each plugin's server half goes on [`server.api`](/docs/reference/server-api) under the same key. See [Plugins](/docs/plugins).

## The access control map

The access control map assigns each route group what it needs: the identity, and the roles it accepts or the permissions the caller has to hold. It is **exhaustive over groups**: every key in `routes` must appear, and public takes an explicit `false`. Build it with [`k.accessControl`](/docs/reference/k-access-control), which lists every form an entry can take. See [Access Control](/docs/access-control) for the walkthrough.

```ts title="access-control.ts"
export const accessControl = k.accessControl(routes, {
    users: false,
    health: false,
    members: 'user',
    workspace: {
        '*': 'member',
        deleteWorkspace: {
            auth: 'member',
            requires: {
                workspace: ['delete'],
            },
        },
    },
});
```

`k.contract` resolves the map onto every route's `security`, `roles` and `requires`, which the [guards](/docs/reference/server-guard), [router](/docs/reference/server-router) types, and [OpenAPI spec](/docs/reference/generate-openapi) all read.
