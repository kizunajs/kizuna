</BetaNotice>

An **identity** is a credential your API accepts. A **guard** turns it into the caller. What that caller may do is [Access Control](/docs/access-control).

<Steps>

<Step>

## Pick your credential

An identity and its guard go together:

<Tabs groupId="credential" items={['Bearer', 'API key', 'Basic', 'Custom']}>

<Tab value="Bearer">

A token in the `Authorization` header.

```ts title="identities.ts"
export const user = Kizuna.identity.bearer({
    context: z.object({
        userId: z.string(),
    }),
});
```

```ts title="guards.ts"
export const requireUser = server.guard('user', async ({ bearer, deny }) => {
    const session = bearer ? await verifySession(bearer.token) : undefined;

    if (!session) {
        return deny({
            status: 401,
            body: {
                detail: 'Unauthorized',
            },
        });
    }

    return {
        userId: session.userId,
    };
});
```

</Tab>

<Tab value="API key">

A value in a header, a query parameter or a cookie. A browser session is `in: 'cookie'`.

```ts title="identities.ts"
export const member = Kizuna.identity.apiKey({
    name: 'x-workspace-token',
    in: 'header',
    context: z.object({
        workspaceUserId: z.string(),
    }),
});
```

```ts title="guards.ts"
export const requireMember = server.guard('member', async ({ apiKey, deny }) => {
    const membership = apiKey ? await findMembership(apiKey.value) : undefined;

    if (!membership) {
        return deny({
            status: 403,
            body: {
                detail: 'Forbidden',
            },
        });
    }

    return {
        workspaceUserId: membership.userId,
    };
});
```

<Callout type="warn" title="A cookie travels on its own">
    The browser attaches it to any request, including ones another site triggers. Set `SameSite` on the cookie and check the `Origin` header
    on unsafe methods.
</Callout>

</Tab>

<Tab value="Basic">

A username and password, decoded from the `Authorization` header.

```ts title="identities.ts"
export const operator = Kizuna.identity.basic({
    context: z.object({
        operatorId: z.string(),
    }),
});
```

```ts title="guards.ts"
export const requireOperator = server.guard('operator', async ({ basic, deny }) => {
    const operator = basic ? await verifyOperator(basic.username, basic.password) : undefined;

    if (!operator) {
        return deny({
            status: 401,
            body: {
                detail: 'Unauthorized',
            },
        });
    }

    return {
        operatorId: operator.id,
    };
});
```

</Tab>

<Tab value="Custom">

A credential no OpenAPI scheme describes, such as a token in a path segment. The guard reads it itself.

```ts title="identities.ts"
export const inviteToken = Kizuna.identity.custom({
    context: z.object({
        inviteId: z.string(),
    }),
});
```

```ts title="guards.ts"
export const requireInviteToken = server.guard('inviteToken', async ({ params, deny }) => {
    const invite = params.token ? await findInvite(params.token) : undefined;

    if (!invite) {
        return deny({
            status: 404,
            body: {
                detail: 'Not found',
            },
        });
    }

    return {
        inviteId: invite.id,
    };
});
```

</Tab>

</Tabs>

`oauth2` and `openIdConnect` are on [OAuth](/docs/oauth).

An identity with no `context` only proves the caller is known. Its guard returns nothing and handlers get no argument for it.

</Step>

<Step>

## Register both

The identity on `new Kizuna()`, the guard on `server.api`:

```ts title="k.ts"
export const k = new Kizuna({
    identities: {
        user,
    },
});
```

```ts title="api.ts"
export const api = server.api({
    router,
    guards: {
        user: requireUser,
    },
});
```

</Step>

<Step>

## Say which routes need it

Every route states its rule, so public is an explicit `false` and a forgotten route is a type error:

```ts title="contract/routes/users.ts"
export const usersRoutes = k.routes('users', {
    listUsers: {
        method: 'GET',
        path: '/users',
        auth: 'user',
        responses: {
            200: z.array(UserSchema),
        },
    },
});
```

```ts title="contract/index.ts"
export const contract = k.contract({
    routes,
});
```

The rest of what an `auth` can say is on [Access Control](/docs/access-control).

</Step>

<Step>

## Read the caller

Every guarded route hands its handler what the guard returned, typed, under `auth`:

```ts title="router/users.ts"
users: {
    listUsers: async ({ auth }) => ({
        status: 200,
        body: {
            users: await findUsersExcept(auth.user.userId),
        },
    }),
},
```

A handler in its own file keeps the typed `auth` via [`RouteHandler`](/docs/reference/server-router)`<typeof contract.routes.users.listUsers>`.

A guard returns the identity's `context`, field for field. Whether that caller may call the route is decided from it before the handler runs, in [Access Control](/docs/access-control). Which rows are theirs is the handler's question.

</Step>

</Steps>

## Denying

`deny({ status, body, headers })` answers with [Problem Details](/docs/reference/problem-details-schema), the same shape `throwError` takes in a handler. A `401` carries the `WWW-Authenticate` challenge RFC 9110 requires, named after the identity that denied it. A cookie or API key has no challenge to send, so those answer `403`.

### What a refusal says

A refusal carries `detail` alone until `guardSchema` widens it:

```ts title="k.ts"
export const GuardSchema = Kizuna.model({
    title: 'GuardDenial',
    schema: ProblemDetailsSchema.extend({
        code: z.enum(['unauthenticated', 'expired_token', 'forbidden']).default('forbidden'),
    }),
});

export const k = new Kizuna({
    identities: {
        user,
        member,
    },
    guardSchema: GuardSchema,
});
```

```ts title="guards.ts"
return deny({
    status: 401,
    body: {
        detail: 'Unauthorized',
        code: 'expired_token',
    },
});
```

Every field you add must be optional or carry a `.default()`, since kizuna sends this body itself when [Access Control](/docs/access-control) refuses a caller. `new Kizuna()` throws when it cannot.

## What else a guard gets

The route's path `params`, the adapter's native request objects, and any [request context](/docs/request-context) the contract declares. A request-scoped value that gates nothing, such as a logger, is a [request context](/docs/request-context) rather than an identity.

## What it drives

`k.contract` puts `401` on every guarded route, as [Problem Details](/docs/reference/problem-details-schema), with `WWW-Authenticate` required when every identity on the route has a challenge and optional when only some do. Declaring a `401` yourself is an error.

[`generateOpenApi`](/docs/reference/generate-openapi) emits your identities as `components.securitySchemes`. A `custom` identity has no scheme, so its routes carry an `x-kizuna-guarded` extension instead.

[`new KizunaClient()`](/docs/reference/kizuna-client) sends the credential in `baseHeaders`, and [MCP endpoints](/docs/mcp) run the same guards per tool call.
