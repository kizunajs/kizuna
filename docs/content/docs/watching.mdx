---
title: Watching
description: Reload a contract when it changes, so nothing you generate from it is ever out of date by hand.
---

Anything generated from a contract falls behind the moment you edit a route. `watchContract` closes that gap: it reloads the contract when any file it was built from changes, and hands you the new one.

You wire it up once. After that you never run a generator by hand.

```ts title="scripts/dev.ts"
import { writeFileSync } from 'node:fs';
import { watchContract } from '@ts-kizuna/cli';
import { generateFetchClient } from '@ts-kizuna/fetch/server';

await watchContract('./src/contract.ts', ({ contract }) => {
    writeFileSync('./src/api-client.ts', generateFetchClient(contract));
});
```

It returns a function that stops watching.

## What it watches

The contract's own import graph, taken from what the loader read. Nothing names a directory, so a route file added three imports deep is watched the moment it is first loaded.

Dependencies are left out, and so is the build output of a workspace sibling, since neither is something you edit.

```ts
await watchContract('./src/contract.ts', ({ files }) => {
    console.log(`watching ${files.length} files`);
});
```

## Every reload

```ts
interface ContractChange {
    contract: Contract;
    changed?: string;
    files: string[];
    notices: Notice[];
}
```

`changed` is the file whose edit triggered the reload, absent on the first load. `files` is the current watch set, which grows and shrinks as your imports do.

## A broken edit

Half-typed files do not parse, and they are the normal state of a file while you are working in it. A reload that throws leaves the last good contract in place, and the watcher keeps going:

```
Could not load the contract after src/routes/users.ts changed.
Unexpected end of input
```

Your next good save recovers. Nothing is written from a contract that failed to load.

Pass `onError` to handle it yourself:

```ts
await watchContract('./src/contract.ts', onChange, {
    onError: (error, changed) => logger.warn({ error, changed }, 'contract reload failed'),
});
```

A contract that is already broken when you start is a different matter: `watchContract` rejects rather than watching something that never loaded.

## Deprecations and sunsets

Every reload reports the routes that announce their own retirement, soonest sunset first:

```ts
import { formatNotice, watchContract } from '@ts-kizuna/cli';

await watchContract('./src/contract.ts', ({ notices }) => {
    for (const notice of notices) console.log(formatNotice(notice));
});
```

```
GET /users/retired  users.retired       sunset 14 days ago
GET /users/export   users.legacyExport  deprecated, sunset in 5 days. Use the reporting API.
GET /users          users.listUsers     deprecated, sunset in 16 days. Use searchUsers instead.
GET /users/search   users.oldSearch     deprecated
```

`daysUntilSunset` goes negative once the date has passed, which is the one you want to notice.

This reads the same [`deprecated`](/docs/deprecations) field the [VS Code extension](/docs/vscode) strikes through in an editor, so a hover and a terminal never disagree.

## Options

| Option       | Description                                                          |
| ------------ | -------------------------------------------------------------------- |
| `exportName` | Named export to read the contract from, `contract` by default        |
| `debounce`   | How long to wait for a run of writes to settle, 60ms by default      |
| `onError`    | Called when a reload throws, reports to stderr when you pass nothing |

## In a dev script

Run it beside your server, and generation stops being something anyone remembers:

```json title="package.json"
{
    "scripts": {
        "dev": "tsx watch src/index.ts & tsx scripts/dev.ts"
    }
}
```

Editors save in bursts, and a compiler writing a directory is a burst of its own, so writes are debounced. Raise `debounce` if your toolchain writes in waves.
