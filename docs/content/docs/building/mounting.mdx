[`defineConfig`](/docs/reference/define-config) brings your routes, identities, jobs and plugins together and hands back the `api` you mount. It lives in `kizuna.config.ts` at the root of your app, which is where the CLI looks for it.

## `kizuna.config.ts`

```ts title="kizuna.config.ts"
import { defineConfig } from '@ts-kizuna/core';
import { expressAdapter } from '@ts-kizuna/express';
import { routes } from './src/routes';
import { user, member } from './src/identities';
import { tags } from './src/tags';

export default defineConfig({
    adapter: expressAdapter(),
    tags,
    routes,
    identities: {
        user,
        member,
    },
});
```

`adapter` decides what every handler receives beside its validated inputs, so naming Express here is what puts `req` and `res` in scope for all of them, typed.

Re-run `kizuna generate` after changing the config, and the `Config` in `kizuna.types.ts` catches up. See [Configuration](/docs/configuration).

## Guards

A guard sits on the identity it authenticates, so `identities` is all the config names. The guard verifies the extracted credential and returns that identity's context or a denial, and a route's `auth` decides which routes it runs on.

An identity a route names has to carry a guard, or the config refuses to assemble. See the [Authentication guide](/docs/authentication).

## Request context

For request-scoped values every handler needs (analytics ids, a logger, the caller's locale), declare them with `k.requestContext`, attach the `handler` that resolves each one, and name them under `requestContext`:

```ts title="kizuna.config.ts"
export default defineConfig({
    adapter: expressAdapter(),
    routes,
    requestContext: {
        analytics,
    },
});
```

Resolvers run on every route, never deny, and handlers receive their values typed under each name. See the [Request Context guide](/docs/request-context).

## Scheduled jobs

[Jobs](/docs/jobs) carry their own handlers, so they go beside `routes`:

```ts title="kizuna.config.ts"
export default defineConfig({
    adapter: expressAdapter(),
    routes,
    jobs,
});
```

`api.mount` then serves the two [job endpoints](/docs/jobs#the-two-job-endpoints), and every handler receives a typed `jobs` runner so a route can run one in process.

## Plugins

[Plugins](/docs/plugins) go under `plugins`, as a list. Each carries the slug your handlers reach it under:

```ts title="kizuna.config.ts"
import { mcpPlugin } from '@ts-kizuna/mcp';
import { openApiPlugin } from '@ts-kizuna/openapi';

export default defineConfig({
    adapter: expressAdapter(),
    routes,
    plugins: [
        mcpPlugin({
            name: 'My API',
        }),
        openApiPlugin({
            info: {
                title: 'My API',
                version: '1.0.0',
            },
        }),
    ],
});
```

Whatever a plugin exports arrives on every handler under `plugins`, keyed by that slug. Their routes are served by `api.mount` and stay out of `api.routes`, so the client and the generators do not see them.

## Middleware

Rate limiting, multipart parsing, and the rest go in your framework's own middleware (`app.use`, Fastify hooks). Authentication belongs in guards, request-scoped values in `requestContext`.

## Mounting

Import the config and mount `kizuna.api`:

**Express:**

```ts title="src/index.ts"
import express from 'express';
import kizuna from '../kizuna.config';

const app = express();
app.use(express.json());

kizuna.api.mount(app);

app.listen(3000);
```

**Fastify:**

```ts title="src/index.ts"
import Fastify from 'fastify';
import kizuna from '../kizuna.config';

const app = Fastify();

await kizuna.api.mount(app);

app.listen({
    port: 3000,
});
```

**Hono:**

```ts title="src/index.ts"
import { Hono } from 'hono';
import kizuna from '../kizuna.config';

const app = new Hono();

kizuna.api.mount(app);

export default app;
```

**Next.js:**

```ts title="src/app/api/[...ts-kizuna]/route.ts"
import kizuna from '../../../../kizuna.config';

export const { GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS } = kizuna.api.mount({
    basePath: '/api',
});
```
