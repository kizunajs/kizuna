`@kizunajs/cli` is the `kizuna` command. It reads your [config](/docs/config) and answers three questions: what should be generated, what does this API serve, and what did this change cost a caller.

<InstallTabs packageName="-D @kizunajs/cli" />

| Command           | What it does                                                                 |
| ----------------- | ---------------------------------------------------------------------------- |
| `kizuna generate` | Writes `kizuna.types.ts`, every client the config declares, and the snapshot |
| `kizuna routes`   | Prints every route the config serves                                         |
| `kizuna diff`     | Compares the config against the same config at a git ref                     |

`--config <path>` points any of them at a config other than `kizuna.config.ts`.

## `kizuna generate`

See [Configuration](/docs/config#kizuna-generate) for what it writes and where.

`--check` writes nothing and exits `1` when anything on disk has fallen behind the config:

```sh title="Terminal"
kizuna generate --check
```

It covers `kizuna.types.ts`, every client under `clients`, and `.kizuna/snapshot.yaml`, so one command answers whether everything generated matches today's config.

```yaml title=".github/workflows/kizuna-checks.yml"
name: Kizuna Checks

on: pull_request

jobs:
    kizuna-checks:
        runs-on: ubuntu-latest
        steps:
            - uses: actions/checkout@v6

            - uses: pnpm/action-setup@v6
            - uses: actions/setup-node@v6
              with:
                  node-version: 24
                  cache: pnpm

            - run: pnpm install --frozen-lockfile
            - run: pnpm kizuna generate --check
```

[Configuration](/docs/config#kizuna-generate---check) has what each file is and where it lands.

In a monorepo, build the other packages your config imports before generating. The config reads their built output, and an out-of-date build loads without complaint.

## `kizuna routes`

Every route, with what it asks of a caller and what it publishes:

```sh title="Terminal"
kizuna routes
```

```text
GET      /users                users.listUsers          auth: public
POST     /users                users.createUser         auth: user
DELETE   /users/:id            users.deleteUser         auth: member, requires workspace:delete  deprecated, use `archiveUser` instead  sunset 2027-01-01
GET      /forecast/:city       weather.getForecast      auth: public  tool: weather_get_forecast
```

The path is the one the server matches, so a route in a group shows the path a caller reaches rather than the one the route declares. A route's `auth` reads as `public`, an identity name, or the identity with the roles and permissions it requires. A route publishing a [tool](/docs/tools) shows the name a model calls it by, resolved the same way the MCP endpoint resolves it.

`--json` prints the same map as an array, for something other than a person to read:

```sh title="Terminal"
kizuna routes --json
```

```json
[
    {
        "key": "weather.getForecast",
        "method": "GET",
        "path": "/forecast/:city",
        "auth": "public",
        "tags": ["weather"],
        "tool": "weather_get_forecast"
    }
]
```

## `kizuna diff`

What a change costs the people already calling your API, against a git ref:

```sh title="Terminal"
kizuna diff --against main
```

```text
BREAKING POST /users body.organisationId is now required

CHANGED  users.patchUser renamed to users.updateUser
         the generated client method changes name, the HTTP surface does not

CHANGED  GET /users/:id can now answer 410
ADDED    POST /users/:id/archive added
```

It exits `1` when a change breaks callers, so a pipeline fails on one. `--against` defaults to `main`, and `--json` prints the changes as an array. See [Breaking changes](/docs/breaking-changes) for what counts as breaking and how to gate a pull request on it.

`kizuna generate` writes `.kizuna/snapshot.yaml` beside your config, and `diff` compares two of those. The base version is read straight out of git, so nothing is checked out, installed or run for the other side, and a comparison against a commit from a year ago costs the same as one against yesterday.

The head version is whatever is on disk, so run `kizuna generate --check` first. A snapshot nobody regenerated compares cleanly against a base it no longer describes.

Two snapshots can also be compared directly, with no git and no config:

```bash
kizuna diff --from base.yaml --to .kizuna/snapshot.yaml
```

## Scripts

```json title="package.json"
{
    "scripts": {
        "kizuna:generate": "kizuna generate",
        "kizuna:check": "kizuna generate --check"
    }
}
```
