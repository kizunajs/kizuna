---
title: One app for every site
description: 'The same site in four countries, each run by its own company, from one Next.js app deployed four times.'
---

One repository, one Next.js app, one CMS config. The app is deployed once per country, and `KIZUNA_SITE` tells each deployment which site it is.

<Steps>

<Step>

## Declare what a site is

A site has a label, a slug, domains and locales. Extend its schema with what yours has:

```ts title="src/cms/site.ts"
import { z } from 'zod';
import { SiteSchema } from '@kizunajs/cms';

export const Site = SiteSchema.extend({
    companyName: z.string().max(60),
    currency: z.enum(['NOK', 'DKK', 'SEK']),
    shopUrl: z.url().optional(),
});
```

## Declare the sites

```ts title="kizuna.config.ts"
content: cms({
    db,
    pages,
    globals: [PrivacyPolicy],
    collections: [Treatments, Centers],
    sites: declareSites(Site, {
        norway: {
            label: 'Example Norge',
            url: 'https://example.no/api',
            locales: ['nb'],
            companyName: 'Example Norge AS',
            currency: 'NOK',
            shopUrl: 'https://shop.example.no',
        },
        denmark: {
            label: 'Example Danmark',
            url: 'https://example.dk/api',
            locales: ['da'],
            companyName: 'Example Danmark ApS',
            currency: 'DKK',
        },
    }),
    site: () => process.env.KIZUNA_SITE,
}),
```

`pages` are the app's, shared by every site. Each site is checked against `Site`, so one missing `currency` fails to compile.

</Step>

<Step>

## Read the site

```tsx title="src/app/(front-page)/page.tsx"
const content = await kizuna.content.pages.frontPage.get();
```

```tsx title="src/components/header.tsx"
const site = await kizuna.content.site.get();

<span>{site.companyName}</span>;
{
    site.shopUrl !== undefined && <a href={site.shopUrl}>Shop</a>;
}
```

`kizuna.content` is the deployment's site. `site.slug` is the union of the sites the config declares, `'norway' | 'denmark'`, so a check narrows and a `switch` is exhaustive:

```tsx title="src/app/(front-page)/hero.tsx"
const site = await kizuna.content.site.get();

switch (site.slug) {
    case 'norway':
        return <HeroNorway />;
    case 'denmark':
        return <HeroDenmark />;
}
```

```tsx
{
    site.slug === 'norway' && <DistributorBanner />;
}
```

A site added to the config makes the `switch` fail to compile until it is handled.

</Step>

<Step>

## What one country has and the others do not

The app is shared, so every site has the same pages with the same fields. When one country needs a field the others must not see, the field names the sites it exists on.

Sweden takes payment by Swish. The contact page has a Swish number for Sweden and nothing of the kind for the others:

```ts title="src/app/contact/content.ts"
export default definePage({
    name: 'contactPage',
    fields: [
        {
            name: 'heading',
            schema: z.string().max(60),
        },
        {
            name: 'swishNumber',
            label: 'Swish number',
            schema: z.string().max(20),
            sites: ['sweden'],
        },
    ],
});
```

|                       | Sweden                             | Norway and Denmark                |
| --------------------- | ---------------------------------- | --------------------------------- |
| In the editor         | The field, required                | Not there                         |
| In the stored content | A value                            | Nothing                           |
| In the type           | `swishNumber: string \| undefined` | The same type, always `undefined` |

The type is the same in every country because the app is the same, so the component checks for the value:

```tsx title="src/app/contact/page.tsx"
const content = await kizuna.content.pages.contactPage.get();

{
    content.swishNumber !== undefined && <Swish number={content.swishNumber} />;
}
```

Without `sites`, the field would have to be optional for everyone, and a Norwegian editor would see a Swish number they must leave empty.

A whole page works the same way. Norway has distributors:

```ts title="src/app/distributors/content.ts"
export default definePage({
    name: 'distributorsPage',
    sites: ['norway'],
    fields: [
        // ...
    ],
});
```

```http title="GET https://example.no/distributors"
HTTP/1.1 200 OK
```

```http title="GET https://example.dk/distributors"
HTTP/1.1 404 Not Found
```

The route exists in the app, and Denmark's deployment answers it the way it answers any address it does not have.

</Step>

<Step>

## Editors

Each country's company edits its own site. The identity says which sites a person belongs to:

```ts
auth: {
    identity: 'editor',
    sites: (editor) => editor.sites,
},
```

```ts
// what the identity carries
sites: {
    norway: ['admin'],
}
```

A deployment shows its own site alone: its editor, its people, its MCP endpoint.

</Step>

<Step>

## Deploy

One project per domain, root directory the app, `KIZUNA_SITE` set per project. `DATABASE_URL` and `KIZUNA_CMS_PREVIEW_SECRET` are the same in all of them. Publishing on one refreshes the others through their `url`.

</Step>

</Steps>
