Your business runs more than one website. Hagen is a group of plant shops with a group site, a shop in the UK and a shop in Norway. All three show the same people, offices and privacy policy, and each has pages of its own. The UK runs events as well.

That shared library is written once, on `cms()`, and the sites sit beside each other over it:

```text
cms()      employees, offices, privacy policy    every site reads these
group      its pages
uk         its pages, its events
norway     its pages
```

A document is shared or belongs to one site, so an editor always knows where a change lands and which sites it reaches.

## Declaring the sites

A site's shape is `SiteSchema`, with the fields your pages need beside `label`, `url` and `icon`:

```ts title="packages/content/src/sites.ts"
import { z } from 'zod';
import { declareSites } from '@kizunajs/cms';
import { SiteSchema } from '@kizunajs/cms/schemas';
import { pages as groupPages } from '../../../apps/group/src/cms.pages';
import { pages as countryPages } from '../../../apps/countries/src/cms.pages';
import { Events } from './events';

export const Site = SiteSchema.extend({
    companyName: z.string(),
});

export const sites = declareSites(Site, {
    group: {
        label: 'Hagen Group',
        url: 'https://hagen.example.com',
        icon: '/icons/group.svg',
        pages: groupPages,
        companyName: 'Hagen Group AS',
    },
    uk: {
        label: 'Hagen UK',
        url: 'https://hagen.example.co.uk',
        icon: '/icons/uk.svg',
        pages: countryPages,
        collections: [Events],
        companyName: 'Hagen UK Ltd',
    },
    norway: {
        label: 'Hagen Norge',
        url: 'https://hagen.example.no',
        icon: '/icons/norway.svg',
        pages: countryPages,
        companyName: 'Hagen Norge AS',
    },
});
```

The shared content goes on `cms()`, beside the sites:

```ts title="packages/content/kizuna.cms.config.ts"
content: cms({
    db,
    collections: [Employees, Offices],
    globals: [PrivacyPolicy],
    sites,
    site: () => process.env.KIZUNA_SITE,
}),
```

`site` says which site a deployment is, and each deployment sets `KIZUNA_SITE`. The UK and Norway render the same countries app, deployed twice, so they share one pages module. Each still keeps its own page documents: the UK's `frontPage` and Norway's are edited and published apart. [Deployment](/docs/cms/deployment) shows the repository.

## Reading

A deployment reads its own site's view. On the UK's deployment, offices are the shared offices with the UK's values in place, and events are the UK's own:

```tsx title="apps/countries/src/app/offices/page.tsx"
const { items: offices } = await kizuna.content.collections.offices.list();
```

The countries app serves two sites, and only one of them has events. `of` narrows the content to the sites an app serves, and checking `site` opens what that site has:

```tsx title="apps/countries/src/app/events/page.tsx"
export default async function EventsPage() {
    const content = kizuna.content.of(['uk', 'norway']);

    if (content.site === 'uk') {
        const { items: events } = await content.collections.events.list();
        return <EventList events={events} />;
    }

    notFound();
}
```

The declared site itself is typed, custom fields included:

```tsx title="apps/countries/src/app/layout.tsx"
const site = await kizuna.content.site.get();

<footer>{site.companyName}</footer>;
```

Over HTTP, every content route sits under its site, at `/content/sites/uk/...`, and a client generated for one site has the same paths as `kizuna.content`. Caches are tagged per site, so a deployment refreshes only what it shows.

## A site's own values on shared content

Every shop shows the shared offices, and the UK answers its phones with its own number. The field says so:

```ts title="packages/content/src/offices.ts"
fields: [
    {
        name: 'address',
        schema: z.string().max(120),
    },
    {
        name: 'phone',
        schema: z.string().max(30),
        perSite: true,
    },
    {
        name: 'openingHours',
        schema: z.string().max(120).optional(),
        sites: ['uk'],
    },
],
```

- **`perSite: true`** lets each site set its own value. A site that leaves it empty shows the shared one, and the editor shows the shared value as the placeholder, with the field marked **Shared** or with the site's label.
- **`sites: ['uk']`** shows and stores the field on those sites alone. A page takes `sites` too, so the countries app's events page exists on the UK alone.

A site's values are that site's draft. Its editors publish them, and only that site refreshes.

## Editors

An editor's sites come from your identity, beside their roles:

```ts title="packages/content/kizuna.cms.config.ts"
auth: {
    identity: 'editor',
    roles: ['editor', 'admin'],
    sites: (editor) => editor.sites,
},
```

`sites` returns a role, or a list of roles, per site, as in `{ uk: 'editor' }`. An editor whose identity carries the role `admin` itself is an admin over every site and the shared content.

| Editor                  | Shared content              | Their site              | Other sites       |
| ----------------------- | --------------------------- | ----------------------- | ----------------- |
| `admin` over every site | Write and publish           | Write and publish       | Write and publish |
| `admin` on a site       | Draft, and ask for a review | As `admin` on one site  | Not shown         |
| `editor` on a site      | Draft, and ask for a review | As `editor` on one site | Not shown         |

Inside a site, the [one-site rules](/docs/cms/editing/permissions#on-one-site) apply as they are. Shared content reaches every site, so an admin over every site publishes it. A site's editor never sees another site, in the admin, the API or MCP. [Who can do what](/docs/cms/editing/permissions#with-several-sites) shows each editor's screen.

## Publishing

Before a shared document publishes, the editor shows where it appears on each site: the pages whose content holds it, and the pages that listed it when they last rendered.

Publishing then refreshes every site and partner that shows the document. Each one gets a job of its own, calling its `invalidate` with `{ brand, id }`, and refreshes the pages that hold the id. The editor shows how it went:

The calls are [jobs](/docs/jobs), so a config with sites names a `jobRunner`, and your transport does the retrying. Unpublishing and deleting send the same call.

## Partners

A partner is a business outside Hagen that shows Hagen's content on its own website. A travel agency sells Hagen UK's garden workshops as day trips, so it reads the UK's events and offices. A partner only reads, so it has no pages or editors here, and the site switcher leaves it out.

```ts title="packages/content/kizuna.cms.config.ts"
content: cms({
    sites,
    partners: {
        travelAgency: {
            label: 'Travel agency',
            reads: ['uk'],
            invalidate: {
                url: 'https://travel.example.com/api/invalidate',
                headers: () => ({
                    authorization: `Bearer ${process.env.TRAVEL_AGENCY_TOKEN}`,
                }),
            },
        },
    },
}),
```

### What it reads

`reads: ['uk']` is the UK's view and the shared content: the offices with the UK's phone numbers, and the UK's events. A read of Norway answers `403`, naming the permission it lacks, `content.sites.norway:read`.

### How it signs in

The travel agency signs in with OAuth client credentials. Your authorization server issues it a client, an `openIdConnect` identity verifies its tokens as on [OAuth](/docs/oauth), and the guard maps the token's client to the partner's name, `travelAgency`. The CMS verifies tokens and never issues them. A read that needs a token answers with `Cache-Control: private`, so no shared cache keeps it.

### What it installs

The partner installs the [client you publish](/docs/cms/api#publishing-a-client) for the UK, a package with the client and the id brands, and calls it with its token:

```ts title="src/lib/hagen.ts"
import { createClient } from '@hagen/uk-content';
import { partnerToken } from './partner-token';

export const hagen = createClient({
    baseUrl: 'https://hagen.example.co.uk/api',
    onRequest: async ({ headers }) => {
        headers.set('authorization', `Bearer ${await partnerToken()}`);
    },
});
```

A partner that runs Kizuna CMS itself holds your ids through a [relationship](/docs/cms/relationships#from-another-kizuna-api).

### How it hears a publish

When a document it reads publishes, the CMS calls the partner's `invalidate` with `{ brand, id }` and the bearer token the partner gave you. The body carries no content, so the partner reads the document again through its client, and a document that was unpublished or deleted answers `404`. A partner hears only what it reads, so a change to Norway never reaches the travel agency. The editor counts partners beside sites, so publishing a shared office reads "Refreshed 3 sites and 1 partner".

## Sites created by admins

Forty dealers, each with a site and a domain, on one app and one deployment. A developer never hears about a new site, since an admin creates it in the editor:

```ts title="src/cms/site.ts"
export const Site = defineSite({
    fields: [
        {
            name: 'theme',
            schema: z.enum(['classic', 'bold']),
            options: {
                classic: 'Classic',
                bold: 'Bold',
            },
        },
        {
            name: 'phone',
            schema: z.string().max(30),
        },
    ],
});
```

```ts title="kizuna.config.ts"
content: cms({
    db,
    pages,
    collections: [Services],
    sites: Site,
}),
```

The admin gives each dealer its label, address and the fields above, and the deployment picks the site from the address a request arrives at. A dealer's editors come from your identity's `sites`, under the dealer's key, and see their site alone. The rules below hold for these sites as for declared ones.

## Starting with one site

A project with one site stores its pages under the site `default`. Content on `cms()` is shared from the start, so adding `sites` moves none of it, and one command gives the pages to their site:

```sh
kizuna cms rename-site default group
```

## The rules between sites

1. A document is shared or belongs to one site.
2. A site reads the shared content and its own, never another site's.
3. Names are unique within a site and the shared content.
4. A site's value for a field shows in place of the shared one, and an empty value shows the shared one.
5. Inside a site, the one-site roles apply, and an admin over every site publishes shared content.
6. Publishing refreshes every site and partner that shows the document, and one that is down never holds up the others.
7. Sites are addressed by their key, like `uk`.
8. Each language is its own copy of a document.
