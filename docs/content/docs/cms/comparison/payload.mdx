## The same page, both ways

An article page that shows the author's name.

<SideBySide>

```ts title="Kizuna: src/app/blog/[slug]/content.ts"
export default definePage({
    name: 'articlePage',
    collection: Articles,
});
```

```ts title="Payload: src/collections/Articles.ts"
export const Articles: CollectionConfig = {
    slug: 'articles',
    fields: [
        {
            name: 'title',
            type: 'text',
            required: true,
        },
        {
            name: 'author',
            type: 'relationship',
            relationTo: 'employees',
        },
    ],
};
```

```tsx title="Kizuna: src/app/blog/[slug]/page.tsx"
const article = await kizuna.content.pages.articlePage.get(await params);
const author = await kizuna.content.collections.employees.get({
    id: article.author,
});
```

```tsx title="Payload: src/app/blog/[slug]/page.tsx"
const payload = await getPayload({ config });
const { docs } = await payload.find({
    collection: 'articles',
    where: {
        slug: {
            equals: slug,
        },
    },
    depth: 1,
});
const article = docs[0];
const author = typeof article.author === 'string' ? undefined : article.author;
```

</SideBySide>

In Kizuna the page is declared beside its route and `author` is an `EmployeeId`. In Payload the page queries a collection and `author` is a string or a document, depending on `depth`.

## Pick Payload when

- Editors want a panel with list views, bulk edit and folders.
- You need GraphQL or MongoDB.
- A plugin already does it: forms, search, e-commerce.
- You want a years-old project with a funded team.

## Pick Kizuna when

- The site has an API of its own and the content should share its types.
- Editors are happy in their chat and on the page.
- Several sites share content without a tenant wall.
- Reviews, roles and on-page editing should come without an enterprise contract.
