---
title: Relationships
description: Records that live outside the CMS, in your own API, another Kizuna API or a service like Stripe, held by id and picked from a list.
---

A page holds ids of records that live elsewhere, and fetches them itself. A relationship gives the editor the list to pick from.

## From your own API

```ts title="src/cms/relationships.ts"
import { defineRelationship } from '@kizunajs/cms';
import { ProductId } from '../models';
import { apiClient } from '../lib/api-client';

export const Products = defineRelationship({
    name: 'products',
    id: ProductId,
    options: async ({ query, ids, headers }) => {
        const result = await apiClient.products.listProductOptions({
            query: {
                q: query,
                ids,
            },
            headers,
        });
        return result.status === 200 ? result.body.options : [];
    },
});
```

`options` feeds the picker: id, label and an optional image. `query` when an editor searches, `ids` for what a field already holds. It runs as the editor, so your route decides what they see.

The route reads only those three:

```ts title="src/routes/products.ts"
listProductOptions: k
    .route({
        method: 'GET',
        path: '/product-options',
        auth: 'staff',
        query: z.object({
            q: z.string().optional(),
            ids: z.array(ProductId).optional(),
        }),
        responses: {
            200: z.object({
                options: z.array(
                    z.object({
                        id: ProductId,
                        label: z.string(),
                        image: z.url().optional(),
                    })
                ),
            }),
        },
    })
    .handler(async ({ query }) => {
        const options = await db
            .select({
                id: products.id,
                label: products.name,
                image: products.imageUrl,
            })
            .from(products)
            .where(query.ids === undefined ? ilike(products.name, `%${query.q ?? ''}%`) : inArray(products.id, query.ids))
            .limit(20);

        return {
            status: 200,
            body: {
                options,
            },
        };
    }),
```

## From another Kizuna API

Every Kizuna collection serves its options, so another Kizuna CMS's [content client](/docs/cms/api#a-client-for-readers) is the picker:

```ts title="src/cms/relationships.ts"
import { z } from 'zod';
import { Kizuna } from 'kizunajs';
import { defineRelationship } from '@kizunajs/cms';
import { headOffice } from '../lib/head-office';

export const EmployeeId = Kizuna.brand('EmployeeId', z.string());

export const HeadOfficeEmployees = defineRelationship({
    name: 'headOfficeEmployees',
    id: EmployeeId,
    options: async ({ query, ids }) => {
        const result = await headOffice.content.collections.employees.options({
            query: {
                q: query,
                ids,
            },
        });
        return result.status === 200 ? result.body.options : [];
    },
});
```

`EmployeeId` carries the head office's brand name, so its ids are the ones this field holds.

## From another service

A Stripe id gets a type of its own, so it never passes for one of yours:

```ts title="src/cms/relationships.ts"
import Stripe from 'stripe';
import { z } from 'zod';
import { Kizuna } from 'kizunajs';
import { defineRelationship } from '@kizunajs/cms';

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);

export const StripeProductId = Kizuna.brand('StripeProductId', z.string());

const findProducts = async (query: string | undefined, ids: string[] | undefined) => {
    if (ids !== undefined) {
        return stripe.products.list({
            ids,
            limit: 100,
        });
    }
    if (query === undefined || query === '') {
        return stripe.products.list({
            active: true,
            limit: 20,
        });
    }
    return stripe.products.search({
        query: `active:'true' AND name~'${query.replaceAll("'", "\\'")}'`,
        limit: 20,
    });
};

export const StripeProducts = defineRelationship({
    name: 'stripeProducts',
    id: StripeProductId,
    options: async ({ query, ids }) => {
        const found = await findProducts(query, ids);
        return found.data.map((product) => ({
            id: product.id,
            label: product.name,
            image: product.images[0],
        }));
    },
});
```

It calls Stripe with your secret key rather than the editor's sign-in, so it leaves `headers` alone.

## Holding them on a page

List each relationship on `cms()`, beside the collections:

```ts title="kizuna.config.ts"
content: cms({
    db,
    pages,
    collections: [Articles],
    relationships: [Products, StripeProducts],
    auth: {
        identity: 'editor',
    },
}),
```

A page field holds the ids:

```ts title="src/app/(front-page)/content.ts"
{
    name: 'featured',
    schema: z.array(Products.id).max(6),
    description: 'Shown in the grid, in this order.',
},
```

The CMS stores and returns ids. The page fetches what it shows, from whichever route and with whichever fields it needs:

```tsx title="src/app/(front-page)/page.tsx"
import { inStoredOrder } from '@kizunajs/cms/next';

export default async function FrontPage() {
    const content = await kizuna.content.pages.frontPage.get();
    const result = await apiClient.products.listProducts({
        query: {
            ids: content.featured,
        },
    });
    const featured = inStoredOrder(content.featured, result.status === 200 ? result.body.products : [], (product) => product.id);

    return <ProductGrid products={featured} />;
}
```

`inStoredOrder` keeps the order the editor chose and drops ids that found nothing, so a deleted product leaves the grid. When a product changes, call [`invalidate`](/docs/cms/api#talking-to-the-app) with the relationship's name, from your own route or from a Stripe webhook, and every page that holds it refreshes.
