---
title: Events
description: 'What runs when content publishes, unpublishes or is deleted. Functions you write, after the fact, that cannot change what was saved.'
---

A collection, a global or a page names what happens after it changes:

```ts title="src/cms/content.ts"
export const Products = defineCollection({
    name: 'products',
    id: ProductId,
    fields: [
        // ...
    ],
    on: {
        published: async (product, { plugins, jobs }) => {
            await plugins.medusa.pushProduct(product);
            await jobs.indexProduct.queue({
                input: {
                    id: product.id,
                },
            });
        },
        deleted: async (product, { plugins }) => {
            await plugins.medusa.removeProduct(product.id);
        },
    },
});
```

| Event         | When                                           | Gets               |
| ------------- | ---------------------------------------------- | ------------------ |
| `published`   | A draft went live, or a published item changed | The published item |
| `unpublished` | An item was taken off the site                 | The last published |
| `deleted`     | An item was deleted                            | The last stored    |

The function gets `plugins` and `jobs`, like a route handler. It runs after the write, so it cannot change what was saved, and an error in it never undoes a publish: the publish stands, and the error is logged with the item. Work that must not be lost goes through a [job](/docs/jobs), which your transport retries.

Drafts have no event. Saving is constant while someone edits, and nothing outside the CMS should react to it.

## For everything

`on` on `cms()` runs for every page, global and item, and gets the item's ref:

```ts title="kizuna.config.ts"
content: cms({
    db,
    pages,
    on: {
        published: async (document, { plugins }) => {
            await plugins.search.index(document.ref, document.content);
        },
    },
}),
```

Refreshing the site's own pages is not an event you write. Publishing already refreshes every page that holds the item, on every [site](/docs/cms/sites/shared-content#publishing-reaches-every-site).

## Validation is not an event

A rule about what may be saved is the field's schema, `z.string().max(60)` or a `.refine()`. A rule about who may save it is `auth` on the field. A rule about when it may go live is [`requireReview`](/docs/cms/reviews#requiring-a-review). None of them run as functions after the fact, so the editor and the model get the same answer before anything is written.
