Each language is its own copy, with its own draft, publish state and address. Try it: change the English summary and publish it, then open NB.

<LocalizationDemo />

```ts title="kizuna.config.ts"
content: cms({
    db,
    pages,
    locales: ['nb', 'en'],
}),
```

The first locale is the source. A site serving several says what to fall back to:

```ts
locales: ['de', 'fr', 'it'],
fallback: {
    fr: ['de'],
    it: ['de'],
},
```

Without `fallback`, an untranslated page is not found in that language. A fallback only shows a published translation.

## Reading

```tsx title="src/app/[locale]/page.tsx"
const { locale } = await params;
const content = await kizuna.content.pages.frontPage.get({
    locale,
});
```

`list`, `getMany` and a global's `get` take `locale` the same way. Over HTTP it is `?locale=nb`. An id is the same in every language.

## What is translated

|                           | Translated | Shared |
| ------------------------- | ---------- | ------ |
| Text and rich text        | Yes        |        |
| Image                     | Alt text   |        |
| Numbers, booleans, dates  |            | Yes    |
| Enums, ids, relationships |            | Yes    |
| Slug                      | Yes        |        |

`localized` overrides the default:

```ts
{
    name: 'productCode',
    schema: z.string().max(20),
    localized: false,
},
```

Shared fields live on the source, are edited there, and publish with it. Change the price once, and every language shows it.

## Addresses per language

A route's folder is its address in code. The page names its address in each language, with the same params:

```ts title="src/app/products/[slug]/content.ts"
export default definePage({
    name: 'productPage',
    collection: Products,
    paths: {
        nb: '/produkter/[slug]',
        en: '/products/[slug]',
    },
});
```

Links are built from the page's name, so a component never writes a path and never knows the language:

```tsx title="src/components/product-card.tsx"
import Link from 'next/link';
import { href } from '@kizunajs/cms/next';

export function ProductCard({ product }: { product: Product }) {
    return (
        <Link
            href={href('productPage', {
                slug: product.slug,
            })}>
            {product.name}
        </Link>
    );
}
```

On the Norwegian site that renders `/produkter/oak-desk`. Serving that address means rewriting it to the route on every request, so it is turned on in the config:

```ts title="kizuna.config.ts"
content: cms({
    db,
    pages,
    locales: ['nb', 'en'],
    paths: {
        rewrite: true,
    },
}),
```

The proxy does the rewrite, and composes with anything else your proxy does:

```ts title="src/proxy.ts"
import type { NextRequest } from 'next/server';
import { contentProxy } from '@kizunajs/cms/next/proxy';
import kizuna from '@kizuna-config';

const rewriteContent = contentProxy(kizuna);

export function proxy(request: NextRequest) {
    return rewriteContent(request);
}

export const config = {
    matcher: ['/((?!api|_next|.*\\..*).*)'],
};
```

`/produkter/oak-desk` reaches `src/app/products/[slug]`, and the folder's own address, `/products/oak-desk`, answers `404` on the Norwegian site. Without `rewrite`, the routes answer at their folders and `paths` feeds only `href`, the sitemap and the language alternates.

## Translating

The language menu beside Live Preview opens another language, and says where each one stands: up to date, how many fields changed in the source, how many are missing. All languages lays every field against every language.

A translation remembers the source version each field came from. When the Norwegian of a field changes and publishes, a dot follows the English field's label. The dot shows the Norwegian before and now, with what changed marked. Update the field, or keep it as it is, since a translation may say it differently on purpose. Until then the page keeps showing the English as it was. Show Norsk puts the source's text under every field.

You can also ask the model in your chat:

> Translate the front page to Norwegian.

## Translating with a model

Name a model, and editors translate without leaving the editor:

```ts title="kizuna.config.ts"
import { anthropic } from '@ai-sdk/anthropic';

content: cms({
    db,
    pages,
    locales: ['nb', 'en'],
    translate: {
        model: anthropic('claude-sonnet-5-5'),
    },
}),
```

`model` is an AI SDK language model, from whichever provider your app uses, with `ai` installed beside it.

Translate, beside Show, counts the fields that changed or are missing, and goes through them one at a time: the source above with what changed in it, the translation under it, and Update, Keep or Translate. Translate everything drafts the rest at once. Done brings the drafted text back to the form as unsaved changes, for a person to read, change, save and publish.

The model writes the text, rich text and alt text from the source's published version, and the slug is made from the translated title. Links, ids and the rich text's structure stay as they are. Agents call the same route as a tool, `POST /editing/pages/frontPage/translate?locale=en`, which saves to the draft. With `save: false` it answers the translation without saving it.

## With several sites

Each site names the languages it serves, from those on `cms()`:

```ts title="packages/content/kizuna.cms.config.ts"
content: cms({
    db,
    locales: ['en', 'nb'],
    collections: [Employees, Offices],
    sites: declareSites(SiteSchema, {
        group: {
            label: 'Hagen Group',
            url: 'https://hagen.example.com',
            icon: '/icons/group.svg',
            pages: groupPages,
            locales: ['en'],
        },
        uk: {
            label: 'Hagen UK',
            url: 'https://hagen.example.co.uk',
            icon: '/icons/uk.svg',
            pages: countryPages,
            locales: ['en'],
        },
        norway: {
            label: 'Hagen Norge',
            url: 'https://hagen.example.no',
            icon: '/icons/norway.svg',
            pages: countryPages,
            locales: ['nb', 'en'],
        },
    }),
    site: () => process.env.KIZUNA_SITE,
}),
```

The first of a site's `locales` is its default, so Hagen Norge opens in Norwegian. Shared content is written once and translated into every language a site serves, so the offices get a Norwegian copy for Hagen Norge. A site's editors draft a translation of shared content, and an admin over every site publishes it. Caches are tagged by site and language.
