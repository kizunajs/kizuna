---
title: Localization
description: Every page in every language the site serves, published one language at a time.
---

Each language is its own copy, with its own draft, publish state and address.

```ts title="kizuna.config.ts"
content: cms({
    db,
    pages,
    locales: ['nb', 'en'],
}),
```

The first locale is the source. A site serving several says what to fall back to:

```ts
locales: ['de', 'fr', 'it'],
fallback: {
    fr: ['de'],
    it: ['de'],
},
```

Without `fallback`, an untranslated page is not found in that language. A fallback only shows a published translation.

## Reading

```tsx title="src/app/[locale]/page.tsx"
const { locale } = await params;
const content = await kizuna.content.pages.frontPage.get({
    locale,
});
```

`list`, `getMany` and a global's `get` take `locale` the same way. Over HTTP it is `?locale=nb`. An id is the same in every language.

`localized` overrides the default:

```ts
{
    name: 'productCode',
    schema: z.string().max(20),
    localized: false,
},
```

Shared fields live on the source and publish with it. Change the price once, and every language shows it.

## Translating

The editor shows one language at a time, with the source beside each field. Ask the model for the rest:

> Translate the front page to Norwegian.

A translation remembers the source version it came from. When a translated field changes in the source, the translation shows as **behind**, and the page keeps showing it until someone updates it.

## With several sites

```ts
locales: ['en', 'nb', 'de'],
sites: {
    norway: {
        locales: ['nb', 'en'],
    },
    switzerland: {
        locales: ['de'],
    },
},
```

Shared content is written once and translated into every language a site serves. Country editors draft, an admin publishes. Caches are tagged by site and language.
