## The products, on a page

A [relationship](/docs/cms/content/relationships#from-another-service) gives the editor Stripe's products to pick from, and the page holds their ids:

```ts title="src/app/(front-page)/content.ts"
{
    name: 'featured',
    schema: z.array(StripeProducts.id).max(6),
},
```

```tsx title="src/app/(front-page)/page.tsx"
const content = await kizuna.content.pages.frontPage.get();
const products = await stripe.products.list({
    ids: content.featured,
    expand: ['data.default_price'],
});
const featured = inStoredOrder(content.featured, products.data, (product) => product.id);
```

## Checkout

A route on the app API creates the session. The fetch client calls it from the cart:

```ts title="src/routes/checkout.ts"
createCheckout: k
    .route({
        method: 'POST',
        path: '/checkout',
        auth: false,
        body: z.object({
            items: z.array(
                z.object({
                    price: StripePriceId,
                    quantity: z.int().min(1),
                })
            ),
        }),
        responses: {
            200: z.object({
                url: z.url(),
            }),
        },
    })
    .handler(async ({ body }) => {
        const session = await stripe.checkout.sessions.create({
            mode: 'payment',
            line_items: body.items,
            success_url: `${process.env.SITE_URL}/thanks`,
            cancel_url: `${process.env.SITE_URL}/cart`,
        });

        return {
            status: 200,
            body: {
                url: session.url!,
            },
        };
    }),
```

## The webhook

Stripe calls one route. It writes the order to your table, and tells the CMS when a product changed so every page that shows it refreshes:

```ts title="src/routes/stripe-webhook.ts"
stripeWebhook: k
    .route({
        method: 'POST',
        path: '/stripe/webhook',
        auth: false,
        hidden: true,
        body: z.unknown(),
        responses: {
            200: z.object({}),
        },
    })
    .handler(async ({ body, headers }) => {
        const event = stripe.webhooks.constructEvent(
            JSON.stringify(body),
            headers['stripe-signature']!,
            process.env.STRIPE_WEBHOOK_SECRET!
        );

        if (event.type === 'checkout.session.completed') {
            await db.insert(orders).values(orderFrom(event.data.object));
        }
        if (event.type === 'product.updated') {
            await cmsClient.invalidate({
                body: {
                    relationship: 'stripeProducts',
                    id: event.data.object.id,
                },
            });
        }

        return {
            status: 200,
            body: {},
        };
    }),
```

## The words around a product

A title, a price and a stock count come from the shop. The description, the gallery, the story and the questions are content. A collection keyed by the product's id holds them, one item per product:

```ts title="src/cms/content.ts"
export const ProductStories = defineCollection({
    name: 'productStories',
    id: StripeProducts.id,
    fields: [
        {
            name: 'description',
            schema: RichTextSchema,
        },
        {
            name: 'gallery',
            schema: z.array(ImageSchema).max(8),
        },
        {
            name: 'questions',
            schema: z.array(
                z.object({
                    question: z.string().max(120),
                    answer: z.string().max(600),
                })
            ),
        },
    ],
});
```

Creating an item means picking the product, so no story exists without one. The product page reads both by the same id:

```tsx title="src/app/products/[id]/page.tsx"
const product = await stripe.products.retrieve(id);
const story = await kizuna.content.collections.productStories.get({
    id: product.id,
});
```

An editor opens the product page in the preview, clicks the description, and writes. Or asks:

> Write a description for the oak desk from its specs, and three questions buyers ask.

## Reviews

Customer reviews are records: customers write them, and they need moderation. They go in your own table, through a route on the app API, and the product page lists them by product id. Testimonials an editor chooses for a campaign page are content, a collection like any other, holding the product's id.

## What editors change

The front page, the campaign pages, and every product's description, gallery and questions. A product's name, price and stock are Stripe's.
