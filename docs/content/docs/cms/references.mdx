---
title: References
description: Point a page at products, authors or anything else in your own tables with a branded id, and keep every page fresh when the item changes.
---

The CMS has no relationship concept of its own. A `Kizuna.brand` id inside a page is a reference: the CMS stores the id and indexes where it is used, and the page fetches the item through the typed routes it already has.

## A branded field

```ts title="src/cms/schemas.ts"
export const ProductId = Kizuna.brand('ProductId', z.string());
```

```ts title="src/app/lp/spring/content.ts"
{
    name: 'featured',
    schema: z.array(ProductId).max(6),
    description: 'Products shown in the grid, in this order. Up to six.',
},
```

Brand names are unique; `kizuna generate` fails when two different schemas share one. Prefix ids from outside services, like `ShopifyProductId`.

## Fetching

The page fetches through the generated client and keeps the stored order. `inStoredOrder` drops ids that found nothing, so a deleted product leaves the grid instead of breaking it:

```tsx title="src/app/lp/spring/page.tsx"
import { inStoredOrder } from '@kizunajs/cms/next';

const content = await cms.pages.springPage.get();
const result = await apiClient.products.listProducts({
    query: {},
});
const featured = inStoredOrder(content.featured, result.status === 200 ? result.body.products : [], (product) => product.id);
```

## The registry

Tell the CMS what it may know about a brand under `brands`. Every entry is optional:

```ts title="kizuna.config.ts"
brands: {
    ProductId: {
        search: products.listProducts,
        label: (product) => product.name,
        image: (product) => product.imageUrl,
        exists: findExistingProductIds,
    },
},
```

| Option   | Used by                                                                       |
| -------- | ----------------------------------------------------------------------------- |
| `search` | A route marked `tool: true`. Powers the picker, and the agent's hint names it |
| `label`  | Picker rows and history                                                       |
| `image`  | Picker thumbnails                                                             |
| `exists` | `kizuna cms push`, which lists ids the target lacks                           |

Without an entry a branded field still works: the preview shows a plain id input, and push skips the check with a warning. The picker runs the search route in process with the search text as `q` and shows the first array in its answer.

## Where-used and invalidation

Every save rebuilds the page's rows in `cms_refs` from its branded fields, and `GET /cms/refs/:brand/:id` lists the pages holding an id. The route that changes an item tells the CMS, and every page featuring it refreshes, no other:

```ts title="src/routes/products.ts"
.handler(async ({ params, body, plugins }) => {
    const product = await renameProduct(params.id, body.name);
    await plugins.cms.invalidate(ProductId, params.id);

    return {
        status: 200,
        body: product,
    };
}),
```
