---
title: Setting up a group
description: One repository for the content package, the shared UI and one Next.js app per site, deployed on its own domain and sharing one database.
---

A group and its country sites live in one repository: the content package holds the CMS config, the UI package holds the components every site renders, and each site is a Next.js app with its own pages and its own deployment. This page sets that up from an empty folder.

```text
packages/
  content/      kizuna.cms.config.ts, the group's collections, shared blocks and fields
  ui/           components every site renders
apps/
  group/        example.com
  uk/           example.co.uk
  norway/       example.no
```

<Steps>

<Step>

## The workspace

pnpm holds the packages, and Turborepo runs builds per app. Pin every shared dependency once in the catalog, so there is one React, one Zod and one Kizuna in the whole repository. Two copies of React break hooks across the package boundary, and two copies of Zod split the registry the CMS's models live in.

```yaml title="pnpm-workspace.yaml"
packages:
    - apps/*
    - packages/*

catalog:
    next: 16.1.0
    react: 19.2.0
    react-dom: 19.2.0
    zod: 4.3.0
    kizunajs: 2.4.0
    '@kizunajs/cms': 2.4.0
    '@kizunajs/next': 2.4.0
```

The packages name those as peer dependencies and the apps hold the real ones, all as `catalog:`. `pnpm why react` shows one copy when it is right.

</Step>

<Step>

## The content package

The content package has no build step. Its `exports` point at source, and each app's Next transpiles it:

```json title="packages/content/package.json"
{
    "name": "@acme/content",
    "type": "module",
    "exports": {
        "./config": "./kizuna.cms.config.ts",
        "./*": "./src/*.ts"
    },
    "peerDependencies": {
        "kizunajs": "catalog:",
        "@kizunajs/cms": "catalog:",
        "zod": "catalog:"
    }
}
```

Import it by its package name, `@acme/content/group`, never through a `paths` alias, since an alias does not cross the package boundary.

The config lists the sites with their pages modules, which the apps generate into themselves, and the group's content:

```ts title="packages/content/kizuna.cms.config.ts"
import { defineConfig } from 'kizunajs';
import { nextAdapter } from '@kizunajs/next';
import { cms } from '@kizunajs/cms';
import { mcpPlugin } from '@kizunajs/mcp';
import { pages as groupPages } from '../../apps/group/src/cms.pages';
import { pages as ukPages } from '../../apps/uk/src/cms.pages';
import { pages as norwayPages } from '../../apps/norway/src/cms.pages';
import { PrivacyPolicy, Employees, Offices } from './src/group';
import { Articles } from './src/articles';
import { UkOffices } from './src/uk';
import { editor } from './src/identities';
import { db } from './src/db';

export default defineConfig({
    adapter: nextAdapter(),
    auth: {
        identities: {
            editor,
        },
    },
    content: cms({
        db,
        locales: ['en', 'nb'],
        globals: [PrivacyPolicy],
        collections: [Employees, Offices],
        sites: {
            group: {
                pages: groupPages,
                app: '../../apps/group/src/app',
                url: 'https://example.com/api',
                locales: ['en'],
            },
            uk: {
                pages: ukPages,
                app: '../../apps/uk/src/app',
                url: 'https://example.co.uk/api',
                locales: ['en'],
                collections: [UkOffices, Articles],
            },
            norway: {
                pages: norwayPages,
                app: '../../apps/norway/src/app',
                url: 'https://example.no/api',
                locales: ['nb', 'en'],
                collections: [Articles],
            },
        },
        auth: {
            identity: 'editor',
            sites: (editor) => editor.sites,
            shared: {
                publish: {
                    roles: 'group',
                },
            },
        },
        signInPath: '/login',
    }),
    plugins: [mcpPlugin()],
});
```

`app` is relative to the content package, which is where `kizuna generate` and every `kizuna cms` command run.

</Step>

<Step>

## Each app

Every app mounts the same config at the same path, so each site serves its own content routes, draft mode and `invalidate`:

```ts title="apps/uk/src/app/api/[...kizuna]/route.ts"
import kizuna from '@acme/content/config';

export const { GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS } = kizuna.api.mount({
    basePath: '/api',
});
```

`basePath` is the config's `apiPath`, which defaults to `/api`. The app's `next.config.ts` collects its own `content.ts` files, and tells Next where the repository root is, so a standalone build traces the content package:

```ts title="apps/uk/next.config.ts"
import path from 'node:path';
import { withKizunaCms } from '@kizunajs/cms/next/config';

export default withKizunaCms({
    output: 'standalone',
    outputFileTracingRoot: path.join(import.meta.dirname, '../../'),
});
```

`withKizunaCms` writes `src/cms.pages.ts` whenever the app starts or builds. Commit it, since the config imports it.

Pages read their own site, and the preview knows which site it is on:

```tsx title="apps/uk/src/app/layout.tsx"
import { KizunaPreview } from '@kizunajs/cms/next';
import kizuna from '@acme/content/config';

export default function Layout({ children }: { children: React.ReactNode }) {
    return (
        <html lang="en">
            <body>
                {children}
                <KizunaPreview content={kizuna.content.sites.uk} />
            </body>
        </html>
    );
}
```

A small module per app keeps the site out of every page:

```ts title="apps/uk/src/content.ts"
import kizuna from '@acme/content/config';

export const site = kizuna.content.sites.uk;
export const group = kizuna.content;
```

</Step>

## The shared UI

Components live in `packages/ui` and read their colours from the app, so one `OfficeCard` renders in every brand. Each app's stylesheet declares its theme and tells Tailwind to look inside the package:

```css title="apps/uk/src/app/globals.css"
@import 'tailwindcss';
@source '../../../../packages/ui/src';

@theme {
    --color-brand: #0f3d5e;
}
```

A component takes a site's own fields as optional, so a site that adds nothing renders as before:

```tsx title="packages/ui/src/office-card.tsx"
export function OfficeCard({ office }: { office: { name: string; address: string; openingHours?: string } }) {
    return (
        <article>
            <h3>{office.name}</h3>
            <p>{office.address}</p>
            {office.openingHours !== undefined && <p>{office.openingHours}</p>}
        </article>
    );
}
```

</Step>

## Environment

One database and one media bucket serve every site, so those variables are shared. The preview secret is shared too: every site signs and checks preview tokens, and a token minted on the group site opens draft mode on the UK site.

| Variable                    | Shared by every app | What it is                                                                         |
| --------------------------- | ------------------- | ---------------------------------------------------------------------------------- |
| `DATABASE_URL`              | Yes                 | The Postgres the `cms_` tables live in                                             |
| `KIZUNA_CMS_PREVIEW_SECRET` | Yes                 | Signs preview tokens. Production refuses to start without it                       |
| `CMS_S3_BUCKET` and friends | Yes                 | The media bucket, see [images](/docs/cms/api#images)                               |
| `SITE_URL`                  | No                  | The site's own origin, for absolute image URLs and the links it tells search about |

Turborepo hides variables it is not told about, so name the shared ones once:

```json title="turbo.json"
{
    "globalEnv": ["DATABASE_URL", "KIZUNA_CMS_PREVIEW_SECRET", "CMS_S3_BUCKET", "CMS_S3_REGION", "CMS_S3_ENDPOINT"],
    "tasks": {
        "build": {
            "dependsOn": ["^build"],
            "outputs": [".next/**", "!.next/cache/**"]
        }
    }
}
```

On Vercel, a shared environment variable linked to the three projects holds each of those, and a project's own variable overrides it where a site differs.

</Step>

<Step>

## The database

The tables are created once, from the content package, never from an app's build. Three apps running the same migration at boot race on one database.

```sh
cd packages/content
kizuna cms migrate --out drizzle
drizzle-kit migrate
```

Run both in a deploy step before the apps deploy, with [`kizuna cms check`](/docs/cms/cli#kizuna-cms-check) after them, so a release stops before visitors see a page that fails its schema.

</Step>

<Step>

## Deploying

Each app is a deployment of its own on its own domain. On Vercel, that is one project per app with its root directory set to the app's folder, and the install filtered to what that app needs:

```json title="apps/uk/vercel.json"
{
    "installCommand": "pnpm install --filter uk..."
}
```

Vercel skips a deployment whose app, workspace dependencies and lockfile did not change, so a change to the Norway app deploys Norway alone, and a change to the content package deploys all three.

In a container, build one image per app from the repository root with `turbo prune uk --docker`, install from the pruned lockfile, build with `turbo build --filter=uk`, and run `node apps/uk/server.js` from the standalone output.

</Step>

<Step>

## Draft mode on every domain

Draft mode is a cookie, and a cookie belongs to one domain. The editor opens each site's own `/api/draft`, which is why every site under `sites` has a `url`. Hosts that refuse to frame a site, like Claude, go through the preview proxy instead, which renders the draft on the server with no cookie in the browser at all.

A starter that sets `X-Frame-Options: SAMEORIGIN` blocks the preview. Allow the editor's origin instead, on the pages it previews:

```ts title="apps/uk/next.config.ts"
headers: async () => [
    {
        source: '/(.*)',
        headers: [
            {
                key: 'Content-Security-Policy',
                value: "frame-ancestors 'self' https://claude.ai",
            },
        ],
    },
],
```

</Step>

## Day to day

| You change                    | Then                                                                       |
| ----------------------------- | -------------------------------------------------------------------------- |
| A page's `content.ts`         | `next dev` regenerates that app's `cms.pages.ts`; commit it                |
| A group collection or a block | `kizuna diff` in the content package says what it breaks across every site |
| A site's own collection       | `kizuna cms migrate` for its indexes, from the content package             |
| An editor's sites             | Their record in your own users, which `auth.sites` reads                   |

`kizuna generate` runs from the content package and writes every site's pages module and client in one go.
