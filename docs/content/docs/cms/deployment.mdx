## A monorepo

Hagen's [sites](/docs/cms/sites) are a group app and a countries app over one content package:

```text
packages/
  content/      kizuna.cms.config.ts, the sites and the shared content
  ui/           components every app renders
apps/
  group/        hagen.example.com
  countries/    hagen.example.co.uk and hagen.example.no, deployed once per site
```

- One React, one Zod and one Kizuna, pinned in the pnpm catalog. The packages list them as peer dependencies.
- The content package has no build. Its `exports` point at source, and apps import it by package name.
- Every app mounts the config at the same `apiPath`, and `withKizunaCms()` in each app's `next.config.ts` collects that app's `content.ts` files into its `src/cms.pages.ts`, which the site's `pages` names.
- Each deployment sets `KIZUNA_SITE` to its site's key: `group` for the group app, and `uk` or `norway` for each deployment of the countries app.
- A config with sites names a `jobRunner`, since every publish refreshes the other deployments, and the [partners](/docs/cms/sites#partners), through jobs.
- `outputFileTracingRoot` points at the repository root, so a standalone build traces the content package.
- `DATABASE_URL`, `KIZUNA_CMS_PREVIEW_SECRET` and the `CMS_S3_*` variables are the same in every app. Turborepo needs them in `globalEnv`.
- `kizuna cms migrate` and `drizzle-kit migrate` run once from the content package, never from an app's build.
- One Vercel project per deployment, so two for the countries app, each with the app as its root directory and `installCommand` filtered to it. A container image is built per app from the repository root with `turbo prune`.
- Draft mode is a cookie per domain, so every site has a `url` and the editor opens each site's own `/api/draft`. A starter's `X-Frame-Options: SAMEORIGIN` blocks the preview, so allow the editor's origin with `frame-ancestors` instead.
