---
title: Drafts and versions
description: 'How drafts are saved, versioned, protected from overwriting, rolled back and unpublished.'
---

- Every save is a version with its author.
- A draft that fails its schema is kept, but never reaches the page. The editor shows what is missing.
- A save that sends `null` for an optional field empties it. A field whose schema accepts `null` stores `null`.
- Two people cannot overwrite each other, since one person edits a document at a time. A client that sends the draft's `ETag` as `If-Match` is also refused with `409` when the draft moved on since it read it.
- Rollback restores an earlier version as a new draft, which you publish separately.
- A draft can publish or unpublish at a time you pick, on its own or with a [release](/docs/cms/editing/releases). See [Scheduling](/docs/cms/editing/scheduling).

## One editor at a time

The first person to save a document holds it. Everyone else sees it read only, with the holder's face and "Kari is editing" where its status goes, until the holder is done. A write from anyone else, a save, a restore, publishing or unpublishing, answers `409` and names who holds it under `heldBy`.

The hold ends when the holder leaves the document, asks for a review of it, or goes two minutes without saving. Nothing else is needed: the next person to save holds it then.

An agent works as the person it acts for, so a model that Mia connected holds a document for Mia, and Mia may keep editing beside it. Between the two of them the later save of a field wins.

`heldBy` on every draft answer and on `editing_describe` says who holds it now, so a model can see it before writing. `editing_release_hold` lets it go once a model is done. A scheduled publish waits while someone holds the document, and goes out once they are done. The app's own writes through the CMS service, like a seed or a migration, take no hold and are never refused by one.

The hold is stored on the document and checked in the same transaction as the save, so it holds across server instances and on a platform that starts a fresh one per request. It needs the `held_by`, `held_since` and `held_until` columns that `kizuna cms migrate` adds to `cms_documents`.

## Unpublishing

Unpublishing withdraws the published copy of a page, a global or an item. The `content` routes stop answering it, and its cache tags revalidate, so the site drops it on the next request. The draft and every version stay, and publishing again brings it back.

An unpublished page reads as not found. An unpublished global sends every page that reads it to `not-found.tsx`, and an unpublished item leaves its collection's lists.

It takes the same permission as publishing, and asks first like publishing does. In the admin, tick items in a collection and press **Unpublish**. A model calls `editing_pages_unpublish`, `editing_globals_unpublish` or `editing_collections_unpublish`.
