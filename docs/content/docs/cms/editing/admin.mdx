Some work needs room. Tagging forty articles, finding last week's orders, or reading a page beside the site it changes is easier on a full screen than in a chat. The admin is that screen. It saves to the same drafts as the chat and the page, under the same rules, so an editor moves between them freely.

## Signing in

The admin is at `/admin` under the CMS's routes, so `/api/admin` with the default `apiPath`. Editors sign in as the editor identity under `auth` on `cms()`, through your app's own auth. Kizuna keeps no accounts and stores no passwords, so you hand it the call that signs an editor in, and the admin draws its own sign-in screen at `/admin/login`. Here `auth` is a [Better Auth](https://better-auth.com) instance:

```ts title="kizuna.config.ts"
content: cms({
    auth: {
        identity: 'editor',
        signIn: ({ email, password, headers }) =>
            auth.api.signInEmail({
                body: {
                    email,
                    password,
                },
                headers,
                asResponse: true,
            }),
    },
}),
```

`signIn` returns the response your auth answers with. Its cookies reach the browser, and any status outside 2xx tells the editor their email or password is wrong, in the same words whichever one it was. A signed-out editor who opens the admin or draft mode lands on the screen, and comes back to where they were going once they are in. The CMS checks that the form was sent from a page of your site, so a form on another site cannot sign an editor in to an account of its choosing.

The foot of the sidebar shows who is signed in, with their role. Give `signOut` the call that ends a session, and their name opens a menu with **Sign out**, which ends the session, closes draft mode, and returns to the sign-in screen:

```ts title="kizuna.config.ts"
content: cms({
    auth: {
        identity: 'editor',
        signOut: ({ headers }) =>
            auth.api.signOut({
                headers,
                asResponse: true,
            }),
    },
}),
```

### Signing in elsewhere

When editors sign in somewhere else, like your company's single sign-on, name that page as `signInPath`. A signed-out editor goes there with `next` naming where they were going. Name the route that ends a session as `signOutPath`, and **Sign out** links to it, so it answers `GET`:

```ts title="kizuna.config.ts"
content: cms({
    auth: {
        identity: 'editor',
    },
    signInPath: '/sso',
    signOutPath: '/logout',
}),
```

Each pair takes one or the other. `cms()` throws when given both `signIn` and `signInPath`, or both `signOut` and `signOutPath`.

## Its address

Editors bookmark the admin, so give it an address they remember. `adminPath` is the path from your site's root, and the sign-in screen sits under it, at `/admin/login`:

```ts title="kizuna.config.ts"
content: cms({
    auth: {
        identity: 'editor',
    },
    adminPath: '/admin',
}),
```

A path under `apiPath` is served by the mount you already have. Anywhere else, like `/admin` above, mount the config a second time at the site's root, from an optional catch-all route at the admin's path:

```ts title="src/app/admin/[[...admin]]/route.ts"
import kizuna from '@kizuna-config';

export const { GET, HEAD } = kizuna.api.mount();
```

With no `basePath`, the route matches the path as the browser sent it, so this file serves `/admin` and `/admin/login`. The admin calls the CMS's routes at `apiPath` wherever it is served, signing in and out among them, and an editor who signs in comes back to `adminPath`.

## The sidebar

The sidebar opens on the [dashboard](/docs/cms/dashboard), and lists everything the editor may open under headings. A heading comes from `group` on a global, collection or view:

```ts title="src/cms/orders.ts"
export const Orders = defineView({
    name: 'orders',
    group: 'Shop',
    fields: orderFields,
    list: searchOrders,
    get: getOrder,
});
```

Pages sit under Content, and so does anything without a `group`. A view the editor may not see is left out, along with whatever else their [access](/docs/cms/editing/access) keeps from them.

⌘K, or Ctrl+K off a Mac, searches everything in the sidebar and every page and item by its title. The arrow keys move through what it finds, Enter opens it, and Escape closes the search.

## Lists

A collection or view opens as a list. Its options decide what the list shows:

| Option    | The list                                                             |
| --------- | -------------------------------------------------------------------- |
| `title`   | The field each row is named by                                       |
| `columns` | The columns it starts with. Each editor can show and hide their own. |
| `search`  | The fields the search box looks in                                   |
| `indexes` | The fields it filters and sorts by, beside the item's status         |

Tick rows and a bar offers **Publish**, **Unpublish** and **Delete** for all of them at once, asking first, as a single publish does. A field holding a list of ids, like an article's `tags`, adds **Add tag** to the bar. A long list comes in pages, with the number of items above it.

A view's list is what its `list` function returns for the search box.

## Editing

An item opens on three tabs:

- **Edit** shows the fields with their [layout](/docs/cms/fields#layout): tabs, rows, collapsible sections and the sidebar.
- **Live preview** puts your site in [draft mode](/docs/cms/next#draft-mode) where the sidebar was, at desktop or phone width. What you type shows on the page as you type it, through [live updates](/docs/cms/next#live-updates). A page opens at its own path, and an item at the page its collection's [`preview`](/docs/cms/collections#live-preview) names, its own page, or the first page that holds it. An item no page shows has no Live preview tab.
- **Versions** lists every draft and published copy, with who saved it. **Compare** shows what changed since, and **Restore** makes that version the draft, which you [publish](/docs/cms/editing/drafts) as usual.

The draft saves a moment after you stop typing, and the header says when it last did. **Save draft** saves at once. **Ask for review** sends it to someone to look at first, as in [Reviews](/docs/cms/editing/reviews), and **Publish** lists every change and asks you to confirm.

## The admin, the page and the chat

All three write the same drafts through the same `editing` routes, so a rule the admin keeps holds for a model too. What differs is how much room each has:

|                     | The admin                  | MCP tools               | A view in the chat           |
| ------------------- | -------------------------- | ----------------------- | ---------------------------- |
| Signing in          | Your editor identity       | OAuth, through the host | The host signs in            |
| Dashboard           | Widgets and charts         | The numbers, as data    | No                           |
| Lists, bulk actions | Search, filters and paging | Change many at once     | No, long lists need room     |
| Editing fields      | Tabs, rows and sidebar     | Saves drafts by field   | A quick change of a field    |
| Live preview        | Beside the fields          | No                      | Depends on the host's frames |
| Versions            | Compare and restore        | List and restore        | No                           |
| Publishing          | Publish, after a confirm   | Always asks first       | The approval, as a card      |
| Actions, like Send  | Buttons                    | One tool per action     | The confirm, as a card       |

A model reads a collection the way the admin lists it, and a nested collection like [tags](/docs/cms/collections#trees) arrives as its tree. [Agents and tools](/docs/cms/editing/agents) lists the tools.
