**Ask for review** sits in the `…` menu beside Publish. Pick one or more people, with the page's owner first, and add a note for them. Send request waits until someone is picked:

<EditorFigure kind="ask" />

The status then reads "Waiting for review by Kari Nordmann". The reviewer sees the request in the editor, in their chat, and wherever you send it with `onReviewRequested`.

</Tab>

<Tab value="Reviewing">

The reviewer opens the page on its **Review** tab. Each change is listed under the tab it sits in, with what is live now beside the draft and the words added or removed marked. They **Approve**, or **Request changes** with a note for the person who asked:

<EditorFigure kind="review" />

Once it is approved, **Publish** sends it live. An approval covers the draft as it was, and a save after it marks the approval outdated.

When changes are requested, the status says who asked for them, and the Review tab shows their note. **Ask Kari again** sends the draft back to them once it is fixed. A review holds one note from each side, the request's and the answer's.

## Requiring a review

```ts title="src/app/investor-relations/content.ts"
export default definePage({
    name: 'investorRelationsPage',
    requireReview: true,
    fields: [
        // ...
    ],
});
```

Publishing waits for an approval from someone other than the person who changed it. Anyone with a role under `reviews.roles` may approve without being asked. The rule holds in the routes, so the model gets the same answer.

## Publishing past a review

Someone with a role under `reviews.roles` can publish before the approval comes. The Publish dialog shows them **Publish anyway** beside the reason Publish is waiting, and asks once more before it goes live:

```ts title="kizuna.cms.config.ts"
reviews: {
    roles: 'admin',
},
```

The publish route takes `{ force: true }` for the same thing. For anyone without one of those roles, `force` changes nothing and the route still answers `409`.

The review records who published past it, with a note like "Published past the review by Grace Hopper", so it is clear afterwards that nobody approved it.

## Several pages at once

The Publish dialog lists every page with changes. Tick the ones to publish, or ask for one review of all of them.

## People

The editor shows people by name and picture. `people.list` reads them from your own users:

```ts title="kizuna.cms.config.ts"
auth: {
    identity: 'editor',
    people: {
        list: async () => {
            const editors = await db
                .select()
                .from(users)
                .where(inArray(users.role, ['editor', 'admin']));
            return editors.map((editor) => ({
                id: editor.email,
                name: editor.name,
                image: editor.image ?? undefined,
                roles: [editor.role],
            }));
        },
        imageOrigins: ['https://lh3.googleusercontent.com'],
    },
},
```

## Owners

A page, global or item can have an owner. The editor shows them beside the page name, and the owner is suggested first for a review.

> Make Kari the owner of the investor pages.

## Sending the request

```ts title="kizuna.cms.config.ts"
reviews: {
    onReviewRequested: async ({ documents, reviewers, requestedBy, note }, { plugins }) => {
        await plugins.resend.sendEmail({
            to: reviewers.map((reviewer) => reviewer.email),
            subject: `${requestedBy.name} asked you to review ${documents.length} pages`,
            text: note ?? '',
        });
    },
},
```
