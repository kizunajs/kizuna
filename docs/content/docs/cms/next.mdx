The CMS targets the App Router, with the CMS API mounted through `@kizunajs/next` in the same app. Reads happen in process, so a static build needs no server to call.

## Reading

`kizuna.content` sits beside `kizuna.api` on the config, typed from every page, global and collection:

```tsx title="src/app/contact/page.tsx"
import kizuna from '@kizuna-config';

export default async function ContactPage() {
    const content = await kizuna.content.pages.contactPage.get();
    return <h1>{content.heading}</h1>;
}
```

| Situation                                | `get()`                                                        |
| ---------------------------------------- | -------------------------------------------------------------- |
| Published                                | The published content, cached and tagged                       |
| Published, but fails its schema          | The newest earlier published version that passes               |
| Not published                            | Calls `notFound()`                                             |
| Draft mode, draft passes the schema      | The draft, marked for the preview                              |
| Draft mode, no draft or incomplete draft | Calls `notFound()`, and `KizunaPreview` shows the setup screen |

Globals and collections read the same way:

```tsx title="src/app/team/page.tsx"
const site = await kizuna.content.globals.site.get();
const { items, next } = await kizuna.content.collections.employees.list({
    where: {
        department: 'design',
    },
    orderBy: 'order',
    limit: 20,
});
```

| Call                                  | Returns                                                                                     |
| ------------------------------------- | ------------------------------------------------------------------------------------------- |
| `globals.<name>.get()`                | The published global, or in draft mode its draft when that passes                           |
| `collections.<name>.get({ id })`      | One item, with its `id`. A missing or unpublished item calls `notFound()`                   |
| `collections.<name>.getMany({ ids })` | The items in the order of the ids, skipping missing and unpublished ones                    |
| `collections.<name>.list(...)`        | Items filtered and sorted by the collection's indexes, and the cursor of the next page      |
| `pages.<name>.get(params)`            | For a page that shows a collection, the item at that address, typed from the route's params |

```tsx title="src/app/blog/[slug]/page.tsx"
export default async function ArticlePage({ params }: { params: Promise<{ slug: string }> }) {
    const article = await kizuna.content.pages.articlePage.get(await params);
    return <h1>{article.title}</h1>;
}
```

A layout that reads a global calls `notFound()` on every route until the global is published, so publish it before the layout ships.

## Rich text

`RichText` renders a rich text field as plain HTML elements. Replace any of them through `components`, keyed the way [`@portabletext/react`](https://github.com/portabletext/react-portabletext) keys them:

```tsx title="src/app/blog/[slug]/page.tsx"
import { RichText } from '@kizunajs/cms/next';

<RichText
    value={article.body}
    components={{
        block: {
            h2: ({ children }) => <h2 className="article-heading">{children}</h2>,
        },
    }}
/>;
```

## Caching

A published read runs inside Next's cache, tagged with what it read: the page, the global, the item, or the collection for a list. Publishing revalidates those tags in process, including every page that references a published item. `nextAdapter()` on the config is what connects the reader to Next's cache, draft mode and `notFound()`.

Draft-mode reads skip the cache, and draft mode makes the render dynamic, so a draft never lands in a cached response.

## Draft mode

Editors enter draft mode at `/api/draft`, which the CMS serves behind the `editor` identity. `?redirect=/blog/welcome` lands them on a page, and `?disable=1` leaves. A signed-out editor goes to the `signInPath` on `cms()` first.

Drafts show only while the editor's sign-in holds. The preview renews a short-lived cookie every few minutes, which only a signed-in editor can, so a shared browser stops showing drafts within ten minutes of the editor signing out.

## The preview

```tsx title="src/app/layout.tsx"
import { KizunaPreview } from '@kizunajs/cms/next';
import kizuna from '@kizuna-config';

<body>
    {children}
    <KizunaPreview content={kizuna.content} />
</body>;
```

It renders nothing outside draft mode. When a layout reads a global, put it in `not-found.tsx` too, since an unpublished global sends every page there and the editor needs the preview to fill it in.

## The content overview

An optional page of your app that lists everything editors can change:

```tsx title="src/app/cms/page.tsx"
import { CmsOverview } from '@kizunajs/cms/next';
import kizuna from '@kizuna-config';

export default function ContentPage() {
    return <CmsOverview content={kizuna.content} />;
}
```

Every page with its status, history and a preview link, an editor for collections and globals, and the media. It also lists content left behind by a renamed page, and published content that fails its schema after a code change. It is a page of your app, so it sits behind your sign-in.

## App data in cached pages

A cached render must never run with a person's credentials. When a page shows app data that is not public, the site's server calls the app API as an identity of its own: an API key with a read-only role, from a server-only environment variable.

```ts title="src/identities.ts"
export const site = k.identity
    .apiKey({
        name: 'x-site-key',
        in: 'header',
        roles: Kizuna.roles(['site']),
    })
    .guard(({ apiKey, deny }) => {
        if (apiKey?.value !== process.env.SITE_API_KEY) {
            return deny({
                status: 401,
                body: {
                    detail: 'Unauthorized',
                },
            });
        }
        return {
            role: 'site',
        };
    });
```

Routes opt in with `auth: ['site', 'staff']`. A leaked key reads what the site reads and nothing more. Keep database imports out of `app/` with `no-restricted-imports`, so every read a page makes goes through a guard.

## Discovery

`withKizunaCms` in `next.config.ts` finds every `content.ts` under `app/` and writes `src/cms.pages.ts` before Next compiles. A page's path is its folder, with route groups and parallel slots dropped the way Next drops them. `kizuna generate` writes the same file, and `--check` fails when it is behind.
