title: Next.js
description: Read content in server components, keep drafts out of every cache, and give cached renders an identity of their own.
---

The CMS targets the App Router with Kizuna mounted through `@kizunajs/next` in the same app. Reads happen in process, so a static build needs no server to call.

## The reader

```ts title="src/cms.ts"
import { createCms } from '@kizunajs/cms/next';
import kizuna from '../kizuna.cms.config';

export const cms = createCms(kizuna.api);
```

`createCms` reads the pages off the api's type, so `cms.pages.<name>.get()` is typed per page.

| Situation                                | `get()`                                                        |
| ---------------------------------------- | -------------------------------------------------------------- |
| Published, outside draft mode            | The published content, cached and tagged                       |
| Not published, outside draft mode        | Calls `notFound()`                                             |
| Draft mode, draft passes the schema      | The draft, marked for the preview                              |
| Draft mode, no draft or incomplete draft | Calls `notFound()`, and `KizunaPreview` shows the setup screen |

Globals and collections read the same way:

```tsx title="src/app/team/page.tsx"
const site = await cms.globals.site.get();
const { items, next } = await cms.collections.employees.list({
    where: {
        department: 'Design',
    },
    orderBy: 'order',
    direction: 'asc',
    limit: 20,
});
```

| Call                                  | Returns                                                                                                                |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `globals.<name>.get()`                | The published global. In draft mode the draft when it passes, the published one otherwise. Neither calls `notFound()`  |
| `collections.<name>.get({ id })`      | One item, with its `id` beside its fields. A missing or unpublished item calls `notFound()`                            |
| `collections.<name>.getMany({ ids })` | The items in the order of the ids, skipping missing and unpublished ones, for the ids a page picked                    |
| `collections.<name>.list(...)`        | A page of items filtered and sorted by the collection's indexes, and the cursor of the next. In draft mode, drafts too |
| `pages.<name>.get(params)`            | For a page that shows a collection, the item at that address. In draft mode the draft at it, then the published one    |

A page at a dynamic route reads its item from the params Next hands it:

```tsx title="src/app/blog/[slug]/page.tsx"
export default async function ArticlePage({ params }: { params: Promise<{ slug: string }> }) {
    const article = await cms.pages.articlePage.get(await params);
    return <h1>{article.title}</h1>;
}
```

The params are typed from the route, so `get` takes `{ slug: string }` here.

A layout that reads a global calls `notFound()` on every route until the global is published, your sign-in page included, so publish it before the layout ships.

Outside draft mode the reader uses nobody's credentials. Published content is public.

## Rich text

`RichText` renders a rich text field with plain HTML elements, `<h2>`, `<strong>`, `<a>`, `<img>` and the rest:

```tsx title="src/app/blog/[slug]/page.tsx"
import { RichText } from '@kizunajs/cms/next';

<RichText value={article.body} />;
```

Replace any element through `components`, keyed the way [`@portabletext/react`](https://github.com/portabletext/react-portabletext) keys them:

```tsx
<RichText
    value={article.body}
    components={{
        block: {
            h2: ({ children }) => <h2 className="article-heading">{children}</h2>,
        },
        types: {
            image: ({ value }) => (
                <Image src={value.image.url} alt={value.image.alt} width={value.image.width} height={value.image.height} />
            ),
        },
    }}
/>
```

In draft mode every piece of text carries its source path, so a click on a paragraph opens the body in the editor.

## Caching

A published read runs inside Next's cache, tagged with what it read: the page, the global, the item, or the collection for a list. Publishing revalidates the tag in process. Publishing an item also revalidates its collection's lists and every page that references it, and the `invalidate` route does the same for an id the CMS does not own, when the app changes it. Hand the plugin `nextRevalidate` to connect the two:

```ts title="kizuna.cms.config.ts"
import { nextRevalidate } from '@kizunajs/cms/next';

const cms = cmsPlugin({
    db,
    pages,
    auth: {
        identity: 'editor',
    },
    revalidate: nextRevalidate,
});
```

Draft-mode reads skip the cache, and draft mode makes the render dynamic, so a draft never lands in a cached response.

## Draft mode

An editor enters draft mode through a token the API mints. The `createPreview` route answers one for a signed-in editor, and the draft route turns it into Next's draft mode:

```ts title="src/app/api/draft/route.ts"
export { GET } from '@kizunajs/cms/next/draft';
```

`GET /api/draft?token=…&redirect=/blog/spring-sale` enables it and redirects; `?disable=1` turns it off. Tokens are signed with `KIZUNA_CMS_PREVIEW_SECRET` and last ten minutes. If the plugin takes `previewSecret` instead, build the route with `createDraftRoute({ secret })`.

## The overlay

```tsx title="src/app/layout.tsx"
import { KizunaPreview } from '@kizunajs/cms/next';

<body>
    {children}
    <KizunaPreview />
</body>;
```

Put it in `app/not-found.tsx` too. A page with no complete draft calls `notFound()`, and Next renders that page without the root layout, so the setup screen needs the overlay there:

```tsx title="src/app/not-found.tsx"
import { KizunaPreview } from '@kizunajs/cms/next';

export default function NotFound() {
    return (
        <main>
            <h1>Not found</h1>
            <KizunaPreview />
        </main>
    );
}
```

A server component that checks draft mode, and a single overlay in the browser however many places render it. The overlay calls the `cms` routes from the browser with the editor's cookies; pass `headers` when editors sign in with a bearer token. `apiPath` and `basePath` default to `/api` and `/cms`; a CMS in [its own API](/docs/cms/api) at `/cms-api` takes `apiPath="/cms-api"` and `basePath="/"`.

## The content overview

```tsx title="src/app/cms/page.tsx"
import { CmsOverview } from '@kizunajs/cms/next';
import kizuna from '../../../kizuna.cms.config';

export default function ContentPage() {
    return <CmsOverview api={kizuna.api} apiPath="/cms-api" />;
}
```

Every page with its status and recent versions, an editor for the collections and globals, the media, and a preview link per page. In the editor you pick an item, change it, and publish it, or add and delete items. Pass `apiPath` when the api is mounted somewhere other than `/api`. It is a page of your app, so it sits behind your sign-in like any other.

## Site identity

A cached render must never run with a person's credentials. Published content needs none, since `getPublished` is public. App data that is not public needs a caller, so the site's server calls the API as an identity of its own: an API key with a read-only role, from a server-only environment variable.

```ts title="src/identities.ts"
export const site = k.identity
    .apiKey({
        name: 'x-site-key',
        in: 'header',
        roles: Kizuna.roles(['site']),
    })
    .guard(({ apiKey, deny }) => {
        if (apiKey?.value !== process.env.SITE_API_KEY) {
            return deny({
                status: 401,
                body: {
                    detail: 'Unauthorized',
                },
            });
        }
        return {
            role: 'site',
        };
    });
```

Routes opt in with `auth: ['site', 'editor']`, and the site's client sends the header from the server. A leaked key can read what the site reads and nothing more.

## Discovery

`withKizunaCms` in `next.config.ts` finds every `content.ts` under `app/` and writes `src/cms.pages.ts` before Next compiles. A page's path is its folder, with route groups and parallel slots dropped the way Next drops them. `kizuna generate` rewrites the same file before it loads the config that imports it, so moving or deleting a `content.ts` never leaves the config importing a file that is gone, and `--check` fails when it is behind. `kizuna cms pages` prints the list.

It lives at `@kizunajs/cms/next/config` because `next.config.ts` runs outside Next's bundler, where `next/headers` cannot load.
