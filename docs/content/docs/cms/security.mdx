title: Security
description: The agent proposes, the server decides, and every change is versioned and signed by a person.
---

Letting a client and an agent change a live site is safe when every rule holds in one place they all go through. That place is the routes.

## Enforced in the routes

Roles, field rules and read-only fields are checked in the `cms` routes. A write to a field the caller may not change answers `403`, a value past its schema answers `422` naming each failure, and a stale `If-Match` answers `409`. The tool descriptions and the greyed-out inputs say the same thing earlier, as a courtesy.

## Drafts by default

Nothing goes live without a publish, and publish and rollback declare `needsApproval`, so an MCP client asks the person first. `kizuna cms push` writes drafts only.

## Signed by a person

Every version records its author from the editor identity's context. The identity is one of yours, so tokens are as short-lived and revocable as you make them. Draft mode needs a token the API mints for a signed-in editor, signed with `KIZUNA_CMS_PREVIEW_SECRET` and good for ten minutes.

## Drafts stay drafts

The public content routes answer published content only. The reader returns a draft in draft mode alone, Next never caches a draft-mode render, and the encoding the preview reads appears there alone, so production HTML carries none of it. A test in the package fails if a draft value reaches a cached response.

## Content is text

A CMS string renders as text. Rich text is Portable Text that `<RichText>` renders, never HTML, and its links are checked against a list of safe schemes. `@kizunajs/eslint-plugin` ships [`no-cms-html`](/docs/eslint#no-cms-html), which flags `dangerouslySetInnerHTML` fed from a page read or an `Output` value. Links in content are `z.url({ protocol: /^https$/ })`, since a plain `z.url()` accepts `javascript:` too.

## Media

Files are checked by their bytes, SVG is refused, location metadata is stripped, and the bucket's credentials stay on the server: the browser uploads through a presigned URL and reads through the image route.

## Its own API

The CMS runs in [its own API](/docs/cms/api), so editor credentials work nowhere in the app API, and an editor's agent sees content tools alone. The app reaches the CMS through one route, `invalidate`, with a key the CMS checks and nothing else accepts.

## Least privilege

The CMS shares the app's database. Connect it as a role limited to its tables, through a Drizzle instance of its own, so a CMS bug cannot reach app data:

```sql
create role cms_editor login password '…';
grant select, insert, update, delete on cms_documents, cms_versions, cms_refs to cms_editor;
```

Give people editor accounts for everyday work and keep admin for the fields marked `auth: { roles: 'admin' }`.

## Pages read app data through routes

A page that imports the database skips every guard the API has. Keep database imports out of `app/` and `components/`:

```js title="eslint.config.js"
{
    files: ['src/app/**', 'src/components/**'],
    rules: {
        'no-restricted-imports': [
            'error',
            {
                paths: [
                    {
                        name: 'drizzle-orm',
                        message: 'Pages read app data through routes, so every read goes through a guard.',
                    },
                ],
                patterns: ['**/db', '**/db/*'],
            },
        ],
    },
},
```

## Cached renders carry no person

ISR and static renders run anonymous or as the read-only [site identity](/docs/cms/next#site-identity). Only a draft-mode render uses an editor's session, and those are never cached. The site key is server-only and read-only.
