An editor opening the [admin](/docs/cms/editing/admin) wants to know what needs them: how the shop is doing, what is waiting for their review, and where to start writing. The dashboard shows that, from widgets you list under `dashboard` on `cms()`:

```ts title="kizuna.config.ts"
content: cms({
    dashboard: [
        {
            type: 'stat',
            label: 'Revenue',
            value: revenue,
            auth: {
                roles: 'admin',
            },
        },
        {
            type: 'chart',
            label: 'Orders per day',
            data: ordersPerDay,
        },
        {
            type: 'reviews',
        },
        {
            type: 'collections',
        },
    ],
}),
```

A widget is a plain object with a `type`, the way a [layout](/docs/cms/fields#layout) item is, and the dashboard shows them in the order listed.

| `type`        | Shows                                                                                                        | Takes                                   |
| ------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------------------- |
| `stat`        | One number                                                                                                   | `label`, `value`                        |
| `chart`       | Bars or a line over time                                                                                     | `label`, `data`, `style`, `description` |
| `reviews`     | The reviews waiting on the person signed in                                                                  |                                         |
| `collections` | Every collection and view they may open, by group, with a count and, on a collection, a **+** for a new item |                                         |

Without `dashboard`, the admin shows `reviews` and `collections`.

Each review waiting names who asked for it and when. Until there is a number to show or a review waiting, the dashboard welcomes the editor above the collections and leaves the period picker out.

## Numbers from your code

A `stat` or `chart` gets its numbers from your function, which runs on your server when the dashboard opens. Revenue can come from Stripe and orders from your own database, since the CMS never needs to hold them. Each function receives `editor`, `plugins`, `period` and, with [sites](#several-sites), `site`.

### The period

The editor picks the period the dashboard counts over, at its top right: the last 24 hours, the last 7 days, the last 30 days or the last 90 days. The dashboard opens on the last 7 days, and names the days beside the picker, like "21 Oct to 28 Oct".

Your function receives the period they picked. A widget's label names what it counts, like "Revenue", and the picker says over which days:

| `period`   | What it is                                                   |
| ---------- | ------------------------------------------------------------ |
| `key`      | `'24h'`, `'7d'`, `'30d'` or `'90d'`                          |
| `from`     | When the period starts, a `Date`                             |
| `to`       | When it ends: now                                            |
| `previous` | The period of the same length just before, as `{ from, to }` |

`previous` is what a stat's change and a chart's comparison count over, so neither needs date arithmetic of your own.

### Stats

`value` returns what the stat shows:

```ts title="src/cms/dashboard.ts"
export async function revenue({ period }: DashboardContext) {
    const total = await revenueBetween(period.from, period.to);
    return formatKroner(total);
}
```

Return `{ value, detail }` to add a line under the number, like "48 orders".

Add `change` to say how far the number moved since the period before, as a fraction: `0.081` shows as ↑ 8.1% and `-0.02` as ↓ 2%.

```ts title="src/cms/dashboard.ts"
export async function revenue({ period }: DashboardContext) {
    const total = await revenueBetween(period.from, period.to);
    const before = await revenueBetween(period.previous.from, period.previous.to);
    return {
        value: formatKroner(total),
        change: (total - before) / before,
    };
}
```

When the period before sold nothing, the division gives no finite number, and the stat shows no change.

Add `trend` to draw a small line beside the number, from values oldest first:

```ts title="src/cms/dashboard.ts"
export async function visitors({ period }: DashboardContext) {
    const days = await countVisitorsByDay(period.from, period.to);
    return {
        value: await countVisitors(period.from, period.to),
        trend: days.map((day) => day.count),
    };
}
```

### Charts

`data` returns the chart's points, oldest first:

```ts title="src/cms/dashboard.ts"
export async function ordersPerDay({ period }: DashboardContext) {
    const days = await countOrdersByDay(period.from, period.to);
    return days.map((day) => ({
        label: formatDay(day.date),
        value: day.count,
    }));
}
```

A chart draws bars. `style: 'line'` draws a line through the points instead:

```ts title="kizuna.config.ts"
{
    type: 'chart',
    label: 'Sales over time',
    style: 'line',
    data: salesPerDay,
},
```

A value is a plain number, and the chart labels its axis from them. `description` names what the numbers count, in a line under the label:

```ts title="kizuna.config.ts"
{
    type: 'chart',
    label: 'Sales over time',
    description: 'Succeeded orders · NOK',
    data: salesPerDay,
},
```

Give a point a `previous` value to compare it with the same point in the period before. The chart draws the period before as a dashed line, or a paler bar, behind this one, with a legend telling them apart:

```ts title="src/cms/dashboard.ts"
export async function salesPerDay({ period }: DashboardContext) {
    const days = await revenueByDay(period.from, period.to);
    const before = await revenueByDay(period.previous.from, period.previous.to);
    return days.map((day, index) => ({
        label: formatDay(day.date),
        value: day.total,
        previous: before[index]?.total,
    }));
}
```

## Who sees a widget

`auth` on a widget keeps it to some editors, written the way a [route's `auth`](/docs/access-control) is: `roles`, or `requires` for permissions. In the config above, editors never see revenue. The server checks it, so a widget's function never runs for someone who may not see it.

The built-in widgets follow the editor's own [access](/docs/cms/editing/access): `collections` lists only what they may open, and `reviews` only what they were asked to look at.

## Several sites

With [sites](/docs/cms/sites) declared, each site has its own dashboard at its address in the admin, like `/admin/uk`. The `dashboard` list runs for the site open, and every stat and chart function receives that `site`: its key and the fields `declareSites()` gave it. Pass the sites to `DashboardContext` to type them:

```ts title="src/dashboard.ts"
export async function visits({ site, period }: DashboardContext<typeof sites>) {
    const total = await countVisits(site.key, period.from, period.to);
    const before = await countVisits(site.key, period.previous.from, period.previous.to);
    return {
        value: total,
        change: (total - before) / before,
    };
}
```

`sites` on a stat or a chart shows it on some sites alone, the way it does on a field:

```ts title="kizuna.config.ts"
{
    type: 'stat',
    label: 'Workshop bookings',
    value: workshopBookings,
    sites: [
        'uk',
    ],
},
```

On a site's dashboard, `reviews` lists what waits on you there, and `collections` lists the site's own collections before the shared ones.

### The overview

An admin over every site opens `/admin` on the overview, which compares the sites. List its widgets under `overview` on `cms()`:

```ts title="kizuna.config.ts"
content: cms({
    sites,
    dashboard,
    overview: [
        {
            type: 'stat',
            label: 'Sales across shops',
            value: salesAcrossShops,
        },
        {
            type: 'sites',
            stats: [
                {
                    label: 'Visits',
                    value: visits,
                },
                {
                    label: 'Sales',
                    value: sales,
                    sites: [
                        'uk',
                        'norway',
                    ],
                },
            ],
            chart: {
                label: 'Visits per day',
                data: visitsPerDay,
            },
        },
        {
            type: 'reviews',
        },
        {
            type: 'reach',
        },
    ],
}),
```

A `stat` or `chart` in `overview` receives `sites`, every site, in place of one. A sum across sites is yours to write, since only your code knows how pounds and kroner add up:

```ts title="src/dashboard.ts"
export async function salesAcrossShops({ sites, period }: OverviewContext<typeof sites>) {
    const totals = await Promise.all(sites.map((site) => kronerBetween(site.key, period.from, period.to)));
    return formatKroner(totals.reduce((sum, total) => sum + total, 0));
}
```

The `sites` widget draws a column per site. It runs the site dashboard's own functions once per site, so each number is written once. The first stat is drawn large over the chart, and the chart is drawn on one scale for every site. Under them, each column shows its reviews waiting, its last publish and its last refresh.

The overview has widgets of its own, from what the CMS records:

| `type`      | Shows                                                                                        |
| ----------- | -------------------------------------------------------------------------------------------- |
| `sites`     | The sites side by side, from the `stats` and the `chart` it names                            |
| `reviews`   | Every review waiting, the shared ones first, then each site's                                |
| `refreshes` | Each site's and partner's last refresh after a publish, and how many answered                |
| `reach`     | Shared items by how many pages show them, on how many sites, with unpublished changes marked |
| `editors`   | Each editor's changes this period, with their role and when they were last active            |

Without `overview`, the overview shows `reviews`, `refreshes` and `reach`.

Nobody else sees the overview, so an editor on one site never sees another site's numbers. An editor who opens `/admin` gets the shared content's `reviews` and `collections`, without stats or charts, since those count for one site.

The `editors` widget names each person's site role from `sites` on what [`people.list`](/docs/cms/editing/reviews#people) returns, like `{ uk: 'editor' }`.
