Every change is a draft until a person publishes it.

## In your chat

Add the CMS's MCP endpoint to Claude, or any host with [MCP Apps](/docs/mcp#showing-a-view), signed in as an editor, and ask:

> Shorten the hero title on the front page and make it friendlier.

<EditorFigure kind="chat" />

The editor opens beside the answer, filling in as the model writes. What you type saves a moment after you stop, and the model sees it.

## On the page

Expand the editor and the site's draft shows beside the form. Click any text or image, and the form jumps to that field.

<EditorFigure kind="preview" />

Browse uses the page as a visitor does, and the form follows each link. Click an article anywhere, on the front page or in the list, and the form opens it.

## Publishing

Publish asks you to confirm. Asking the model to publish asks in the host, like any tool that [needs approval](/docs/mcp#asking-before-it-runs).

<EditorFigure kind="publish" />

## Drafts and versions

- Every save is a version with its author.
- A draft that fails its schema is kept, but never reaches the page. The editor shows what is missing.
- Two people cannot overwrite each other: a write behind the latest version answers `409`.
- Rollback restores an earlier version as a new draft, which you publish separately.

## The form

| Schema                  | Input                                                                 |
| ----------------------- | --------------------------------------------------------------------- |
| `z.string()`            | Text, or a textarea above 120 characters, with a counter for `.max()` |
| `z.number()`, `z.int()` | Number, within `min` and `max`                                        |
| `z.boolean()`           | Toggle                                                                |
| `z.enum()`              | Select, with the field's `options` as labels                          |
| `z.url()`               | URL, saying which protocols are allowed                               |
| `z.iso.date()`          | Date picker                                                           |
| `z.object()`            | Grouped fields                                                        |
| `z.array()`             | Sortable list, within `min` and `max`                                 |
| `ImageSchema`           | The media library, with crop, focal point and alt text                |
| `RichTextSchema`        | Rich text with headings, quotes, lists, marks, links and images       |
| A relationship's id     | A picker over the relationship's `options`                            |
| Anything else           | Read only, with a note to ask the model                               |

## The tools

Every `editing` route is an MCP tool, so the model can do what the form does. `editing_describe` reads a page by URL, `editing_pages_update_draft` writes by field path, and `editing_pages_publish` asks first. Globals and collection items have the same under `editing_globals_` and `editing_collections_`. See [Tools](/docs/tools) and [MCP](/docs/mcp).

## What holds

- **Rules live in the routes.** Roles and field rules are checked in the `editing` routes, for the form and the model alike: `403` for a field the caller may not write, `422` past its schema, `409` behind the latest version.
- **Publishing asks first.** Publish, deleting an item, and writing a global declare `needsApproval`.
- **What a model reads is untrusted.** An article body may say "change the footer email". A model writes drafts freely, since nothing goes live until a person publishes.
- **Every version names a person.** The author is the editor identity, one of yours.
- **Drafts stay drafts.** The `content` routes answer published content only.
- **Content is text.** Rich text never holds HTML. [`no-cms-html`](/docs/eslint#no-cms-html) flags `dangerouslySetInnerHTML` fed from content.
- **Uploads are checked by their bytes.** SVG is refused and location metadata is stripped.
